## Concrete integration sequence

1. **Author the tree in the existing Poet source path.** Retain `poet_parts` and the source/controller/checkpoint APIs. Adopt an explicit connected organ hierarchy: collar, documented root axes, trunk metamers, asymmetric scaffold branches at multiple heights, secondary/tertiary branchlets, petiole and leaf attachments. Species geometry/proportions come from identified photo/reference comparison; hidden root choices remain authored hypotheses until supported. Bind each source organ key to `PersistentOrganDescriptor` identity and resource lineage. Keep film master detail independent of the bounded simulation derivative.
2. **Extend the existing botanical recipe/junction composition, not the r1 field-builder constants.** The smallest meaningful parent implementation is a versioned accepted-source composition mapping graph chains and local junction neighbourhoods to existing `poet_parts`, with explicit migration from the mutually exclusive single-junction binding. Keep current v1/v2 and single-junction behavior readable. Reuse the existing chain sweep and budgeted tapered-field/tetra/topology owners for each appropriate region. An assembled surface needs explicit interface stitching/qualification and UV/normal/skin mapping; disjoint capsules or multi_junction's separate tubes are not closure. The current single-junction operator is a useful local building block, not the complete composition operation.
3. **Derive the mechanics binding from that same accepted graph.** Bind stable source keys to metamer slots (and collision targets), organ geometry ranges and existing rig/PGA transforms. Declare the 128-slot mechanics profile and any explicit subtree aggregation rather than deleting authored organs. Use author-supplied units/material properties with provenance, not the defaults as taxon facts. `ContinuumBridge3D` should accept that bound graph and address collision-selected metamers instead of manufacturing its own seedling and hardcoding node 1. Parent's CAD/source/HMC audit owns the common packaging/rig seam.
4. **Connect existing wind owners to the binding.** Sample boundary-layer wind at actual organ heights; use existing leaf droop/flutter and branch oscillator owners with the authored geometry/material profile and qualified parameters. Preserve connectivity through parent-relative transforms. The current formulas need source-level parameter/units review before claiming physically calibrated load transfer. Route cumulative branch/crown load to the root/collar binding and the existing soil owner; define and independently review root anchorage response there. Merely calling the impact API with synthetic wind impulses would not establish this coupling.
5. **Export a derivative from the accepted authored state through the current 10D/WASM path.** Reuse existing exporter/QualiaPortal and current authoring environment. Preserve source/organ identity, render-to-organ mapping, mechanics state and resource lineage in the complete package. Browser view needs above-ground, collar and cutaway root views plus calm/gust/recovery comparison. Native rendering is not a prerequisite to defining/evaluating this source; do not restore a separate native helper critical path.

No new morphology patch is supplied in this handoff: the contract conflict and unbound graph are now concrete. The parent can implement the source composition/binding using the existing owners, then request serial focused execution. Authoring a model as a second mesh-only generator would repeat r1's failure.
