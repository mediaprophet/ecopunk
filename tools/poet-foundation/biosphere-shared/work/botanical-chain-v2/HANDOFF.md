# Opt-in native botanical linear-chain profile: staged

**Uninstalled, uncompiled, untested.** `manifest.tsv` pins each existing preimage and candidate. Integrator owns shared-file merge, review and serial testing. This is a bounded degree-two improvement, not a fork-junction solution or biological/visual-quality claim.

Existing Poet `botanical_graph_host::evaluate` calls QualiaDB `extrude_profile_along_path` once per edge and caps each end. Existing Core sweep accepts a multi-station path, uses Bishop frames and caller buffers. The explicit v2 candidate groups consecutive single-child edges into maximal chains and calls that existing sweep per chain, preserving all source keys and computed radii. A fork starts separate fully capped chains; they remain disconnected, may overlap, and are not watertight or smooth-merged. Tight bends can invert or self-intersect despite edge-incidence checks.

V1 source and evaluator paths are unchanged: schema `poet.botanical/v1`, version `1`. Opt-in v2 uses schema `poet.botanical/v2`, version `2`; readers prior to this change reject the v2 pair. Schema/version mismatches refuse. The typed form defaults to v1 and offers v2 as a named choice. The existing graph inspector stages explicit upgrade using the existing `SetRecipe` route, checking the live source, publication and selected part, while retaining the recipe's organ keys and parameters. Surface topology changes are never implicit; authored geometry streams and indexed atlas edits must continue to fail closed unless the separate reviewed preservation candidate qualifies them.

The legacy worst-case per-edge mesh bound dominates the new chain mesh. For v2, validation additionally charges two vertex-work units per organ before allocations against the existing host-selected max-vertices limit (itself work/scratch derived). This is a conservative accounting unit, not a measured memory bound. No changes to QualiaDB, external libraries or product JSON formats.
