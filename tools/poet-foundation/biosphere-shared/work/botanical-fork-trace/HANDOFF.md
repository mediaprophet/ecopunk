# Fork junction feasibility: selected QualiaDB sources

Scope: source inspection, one in-memory sign-mask diagnostic and a separately staged polygon-soup owner repair. No Cargo, GUI, production asset, junction mesh or human review. User's desired outcome is connected, author-controlled branch junctions; this note does not close that requirement.

`computational_geometry/sdf_ops.rs` exports caller-buffer-free scalar `sdf_capsule` (constant radius) and `sdf_smooth_union` (blend radius, ordered pairwise). True taper needs an explicit and qualified field contract; interpreting a varying-radius distance-to-segment formula as an exact SDF would be misleading. Blend order, bounds, tolerance, resolution, distances and source/UV lineage need author-controlled, persisted semantics.

`isosurface.rs::marching_cubes` uses caller-owned buffers but outputs per-cell vertices, with upper scratch lengths based on `(nx-1)*(ny-1)*(nz-1)*30` vertices and `*10` triangles; callers must bound/check arithmetic before invoking it. It chooses `TRI_TABLE[cube_idx]` using only the signs of the eight scalar samples. Its header calls the table ambiguity-resolved, but no scalar-dependent face/interior decision is apparent in the inspected path. For a checkerboard bilinear face, samples (-2,+1,-2,+1) and (-1,+2,-1,+2) share corner signs but have opposite determinant signs (+3 and -3). A fixed sign-only lookup cannot distinguish those two cases. This observation establishes a qualification gap, not by itself proof of a crack in a particular output. An independent static enumeration of all sign-consistent adjacent-cell x-face mask pairs found no mismatched table edge-pairings, but did not qualify other shared faces, interior ambiguity or geometry.

A deliberately conservative illustrative sign-mask prefilter in `conservative-sign-mask-check.py` evaluated a synthetic three-arm blended tapered field on 16 cubed cells. It counted 296 surface cells and refused 13 non-face four-inside configurations. This indicates that the naive fail-closed mask would reject that representative input, not that no safe connected surface is possible. The diagnostic uses no QualiaDB calls and is not an engine test or a species reference.

`polygon_soup::merge_vertices` is public and `repair_polygon_soup` calls it. Its original scan indexed candidate representatives from the input array instead of the compacted output; A,A,B,B produces three representatives rather than two. The minimal zero-heap/caller-buffer repair and focused owner plus Poet public-caller tests are staged at `../polygon-soup-weld-fix`; those tests have not run. Existing `topology::build_triangle_half_edges` rejects duplicate directed/nonmanifold edges and reports boundaries but does not establish one connected component, every vertex link being a single fan, or no self-intersection. `tri_tri_3::self_intersecting_pairs` is a cold internal Vec-backed builder and skips all shared-vertex pairs; it cannot alone establish absence of all foldovers. `boolean_3` documents approximate f64 construction and near-coplanar limitations, so blindly unioning intersecting branch sweeps is not qualified.

A safe connected-fork implementation needs an explicit bounded numeric/topology contract, an ambiguity-aware extraction method or justified fail-closed accepted subset, canonical edge welding that cannot hide genuine cracks, closed oriented edges and vertex links, connected-component checks, geometric intersection/foldover treatment, validated continuity/seam/source mapping, preflighted work and scratch, and author-controlled taper/blend. These are implementation and verification requirements, not proof that all such work is absent elsewhere.
