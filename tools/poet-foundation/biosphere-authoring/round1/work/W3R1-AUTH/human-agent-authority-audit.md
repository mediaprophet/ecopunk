# Human principal and delegated agent authority — bounded source audit

2026-10-26. User steering: authentication must have a hierarchy considering the human principal and rights pertaining to agents. **The human-principal → delegated-agent production-authority gate remains OPEN.** Current native Poet sessions prove an admitted actor's controller-key possession and project admission; they do not yet prove that a particular human adopted a bounded delegation to that agent. This is a read-only audit and proposed next contract, not implementation, adopted permission or human acceptance. Prior staged successors remain frozen.

Exact selected source ranges and SHA-256 pins for 33 files are in [human-agent-authority-audit.coverage.json](human-agent-authority-audit.coverage.json). Source references below use inspected local APIs; downstream bodies beyond recorded ranges are not semantically audited. No Cargo, check, test, provider, asset, credential-store or signing operation ran. Source tests mentioned below were not executed in this audit. No canonical changes occurred.

## Authentication, human authority and project permission are distinct

The human principal is the person whose authority an agent acts under. The acting software agent keeps its own subject, identifiers, controller key, software/version/capacity and actual actions. A project trust anchor admits project membership; it does not automatically become every person's authority to delegate. The human need not log in for each action when a valid adopted bounded delegation permits unattended work, but their control over that delegation must remain effective and inspectable.

Existing vocabulary needs preservation: `PrincipalKind` currently classifies authenticated actors as Human, SoftwareAgent or Organization. Keep those exact API spellings when citing or migrating source. Do not silently reinterpret every existing `AuthenticatedPrincipal.subject` as the delegating human, or change an agent's recorded kind to Human. Qualified identifiers remain associations; matching strings/short hashes, a profile label or one DID do not create an authority relationship.

## Implementable next contract and ownership

This is a proposed bounded adaptation of existing owners, not a second auth system or activated implementation batch.

1. **Freeze a human-principal/delegated-actor authority context in cooperative-core.** Preserve the existing actor `PrincipalKind` and project membership APIs. Compose the existing `AgencyDelegation`, `TaskDelegation` effects/modes/budgets and `AgentRef` / `JudgementProvenance` distinctions into one reviewed contract. Its host-verified projection must expose the qualified human principal/root, actual acting agent/controller, adopted immutable delegation/release digest, parent references and current status. A project signer may admit the relationship to its project; that signature cannot substitute for the human principal's authorization of the delegation. Any exceptional non-consensual legal authority must have a separately qualified source/authority path, not an inferred default.
2. **Adopt exact bounded grant semantics.** Bind issuer/grantor and grantee controller associations, project/document/resource selectors, actual AuthoringAction/effects/commands, purpose, validity, approval mode and resource budgets to the signed/adopted bytes. Reuse native key owners and appropriate existing credential/VC verification; retain provenance and adoption separately from proof of origin. Do not grant from request strings or accept `consent: Granted` merely because a source JSON says so. Source arguments are requested operations to compare with host-owned authority.
3. **Make subdelegation explicit and attenuating.** Default to no onward delegation. If adopted policy permits it, each child must name an exact parent digest and its grantor must equal the parent's admitted grantee. Bound hop/count/text budgets, reject cycles/unknown parents and require child actions/resources/purpose/time/budgets to be within the current parent's constraints. Reuse `attenuates` / CRL traversal only after full edge admission; short graph keys remain indexes. A principal's revocation/withdrawal/expiry or an intermediate grant change invalidates dependent sessions/permits/publications. Independent principals/delegations remain distinguishable; never silently evict unrelated sessions. An initial coarse global admission-generation invalidation may remain explicit while finer dependency invalidation is qualified.
4. **Intersect hierarchy rights with existing permissions at the native owner.** Actor key proof remains mandatory. The current native-authority lock still encloses chain freshness, project role/review scope, exact source/expected package, action admission, actual operation and durable evidence. The effective authority is the intersection of project admission, current human-rooted delegation/parent chain, native effect grants and task budgets. No delegated agent can acquire steward/reviewer/provider/network/payment rights simply because it can author source. Observe, Propose and ApproveEachAction require actual dispatch semantics; an approval must bind the intended operation and source/package context, not a generic UI boolean.
5. **Preserve actor, principal and responsibility in durable records.** Extend existing contribution/review/package-write audit records with human authority root and immutable delegation path/digest/status generation and operation/purpose evidence. Keep the actual actor and software kind, human authorship/review acceptance, source ownership and paid/unpaid status separate. Use `JudgementProvenance` to record reliance; it is not itself authority. Do not transfer all agent-produced authorship/compensation to the principal without the project's adopted contribution terms.
6. **Check review independence across the authority hierarchy.** Current subject-only self-review denial is insufficient for two agents controlled by one human. Define the reviewed conflict policy over human control/delegation ancestry as well as actual contributors, exact source/package lineage and explicit review scope. An agent review cannot close a human-acceptance gate, even when its principal is human. Preserve independent human review requirements; do not fabricate a second reviewer by issuing another key.

Canonical owners for the next implementation are cooperative-core (authority/delegation and audit contract), Core `native_authority` (verified host adapter/lifecycle/journal), QDNF authority (scope/operation-consumption repair where required), and existing Poet native enrollment/selection/controls (principal visibility, delegation/adoption/revoke and actual operations). Shared app-contract types remain the application effect/mode/budget vocabulary. Source signing/approval belongs to existing native key/credential owners; no sibling repository edits are authorized by this audit.

## Compatibility and acceptance work

Version the new adopted delegation context explicitly. Keep old admissions/journals readable as **legacy direct-admission evidence with no proven human delegation**. Do not backfill a human principal, grant, acceptance, signature or revocation history. Preserve software-agent fixture tests under an explicit engineering profile; production delegated-agent admission must fail closed when the required human-rooted proof is missing. The transition policy for existing direct software memberships needs an explicit reviewed migration decision, not silent privilege escalation or silently breaking stored records. Direct authenticated human action remains a distinct path.

**Outcome:** reuse foundations exist, but this inspected native Poet path does not yet establish the human principal → scoped agent hierarchy requested. Keep that gate, IP-03 human acceptance and asset production HOLD visible. No model/package completion is asserted.
