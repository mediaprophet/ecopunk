## Existing seam and implemented behavior

`NativeAuthority::begin_session` previously replaced one pending proof. `complete_session` consumed that singleton, revoked the previous session, reset the existing QDNF owner and incremented the global generation. A reviewer login therefore invalidated an unrelated author. The same singleton also supplied steward and package-administration audit attribution.

The candidate keeps the existing signed project admission, contextual Ed25519 key proof, QDNF grant and pure cooperative policy owners. It adds no authentication transport or grant language. One authority still exclusively owns the journal and shared document, and its single mutex still encloses authorization, actual operation, source successor validation and durable evidence commit.

- Fixed arrays hold **16 authenticated sessions** and **32 outstanding challenges**. These are explicit concurrent working limits, not a content/master quality budget. Subject text remains bounded by signed admission verification. A live session owns one existing fixed eight-record QDNF `GrantOwner`; retired owners cannot exhaust another session's retained revoked slots. No new unbounded table is introduced.
- Each proof binds the process incarnation, fresh nonce, adopted admission digest, admitted controller public key, bounded expiry and length-delimited project/subject identifiers using the unchanged session context. Completion matches every opaque challenge field before taking its slot. A wrong signature for that exact challenge consumes only that one-use challenge. Foreign, replayed or tampered challenge fields cannot consume an unrelated pending proof.
- Expiry is bounded to 1–3,600 requested seconds and capped by both admitted subject and adopted project validity. Each session checks its own expiry and its own existing QDNF execution grant before canonical read policy. Expired entries are reclaimed on subsequent begin/complete calls. Expiry always denies immediately even before reclamation.
- `disconnect(handle)` revokes/removes only that opaque session. Same-subject sessions remain independent. New `cancel_session_challenge(&challenge)` cancels exactly one pending challenge. Capacity errors never silently retire a live session; a completed proof refused for live capacity is consumed and requires a fresh challenge after capacity is released.
- Login/logout/expiry no longer increment the shared generation. **The generation denotes adopted admission changes.** Opaque handles supply independent session freshness. Signed replacement and signed enrollment/review-grant changes retain intentional global invalidation: after successful durable append, all pending/live entries are removed and generation advances. Failed signed replacement leaves existing live state intact; journal failures retain the existing reconciliation latch.
- Source commit attribution uses the actual selected session's already captured principal, rather than the last logged-in actor. Enrollment permissions resolve their own handle for steward role checks and audit attribution. Existing requests never grant roles.

## Source, publication and package compatibility

The existing `publication_is_current(handle, generation)` remains an authority-only nonblocking guard. A valid unrelated login/logout leaves it current; selective logout, expiry, foreign process handle, admission replacement, reconciliation or contention refuses it. Consumers must retain their existing exact `SourceRef` check. A source edit does not require every authenticated actor to log in again.

The additive `source_publication_is_current(handle, generation, expected_document)` checks the exact current durable `DocumentRevision` under the same nonblocking lock. A successor makes an old document context stale while the same handle can read fresh state. This is durable metadata freshness, not continuous verification of externally changed source bytes. Poet's `NativeAuthorityOwner::source_transaction`, `with_authorized` and `SourceRef::check_current` remain responsible for actual source-store correspondence. Package publication retains the existing exact saved package/source/lineage checks, expected-file policy, trusted file callback and journal preflight; those owners were not replaced.

Public method signatures are preserved. New public API consists of the two capacity constants, pending cancellation and optional source-bound publication guard. No durable schema changes occur. Fresh `open`/`open_retained_current` creates empty process-local tables; journal records still cannot restore sessions.
