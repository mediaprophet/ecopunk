# Staged in-place Sheet formula work — not installed

The existing QualiaDB `Sheet.eval_formula` dispatch presently creates a synthetic Studio receipt, claims a cached numeric result without evaluating, and writes an artifact to STUDIO_STORE. This candidate instead uses GridCraft's existing typed formula parser, workbook and calculator directly from the existing QualiaDB owner. It introduces no new JSON data model, storage or adapter interface. It is a stateless numeric calculation, not workbook admission, persistence, or complete human editing.

`manifest.json` records candidate files and canonical preimages; merge `sheet/mod.rs` with concurrent Sheet.set_cell work and `graphical/mod.rs` with other coordinated tests instead of replacing a newer version. Verify all preimages and user work before installation. `source-pins.json` hashes all files under the six reachable Craft crates and relevant workspace manifests, lock and notices; it is not a semantic audit of each file or a Git revision pin. A live path dependency can drift and needs revalidation. Copies of both licenses, NOTICE and ATTRIBUTION are staged for placement according to the coordinator's third-party notice policy.

Existing dispatch `Sheet.eval_formula` and op/id/formula/ast_depth/result_type/cached fields remain; depth is actual, cached is false, and `value` contains a finite number or the spreadsheet error string. This deliberately removes the fabricated receipt and its artifact_id/did/clock/quins and STUDIO_STORE side effect: an observable compatibility migration. Source search found the Webizen studio demo as direct in-tree caller; its candidate now passes the 2x2 grid. Unknown external callers may depend on the old receipt. Capability authorisation remains that of the existing dispatch.

Requests use the existing Vibe record with `formula` and optional `grid` (numeric list of row lists); references require an explicit grid. Ragged/absent cells have GridCraft empty-cell semantics. Formula input <=256 bytes, parsed AST <=64 nodes/depth 16, numeric grid <=32x32, calls <=8 arguments. Allowed operations are current-sheet cell and bounded range refs, finite literals, unary +/-/percent, + - * /, and SUM/AVERAGE/MIN/MAX/COUNT. All other parsed forms are refused; non-finite inputs, inexact integers beyond 2^53 and non-finite scalar outputs are refused. Craft's calculator returns spreadsheet errors as values. Inputs and syntax are bounded, but peak memory and execution time are not measured and no dynamic cancellation is claimed.

Dependencies add local gridcraft-core/formula/model/calc and transitively functions/numfmt. Their external normal dependencies are serde, thiserror, log and regex. Both QualiaDB and Poet lockfiles need a carefully reviewed coordinated offline update and reproducibility review; no lockfile has been modified. Toolchain, local path availability, WASM support, no-JS target closure and third-party license attribution need actual qualification. Keep Craft sources read-only and preserve MIT/Apache notice choices. Numeric formula subset does not migrate the legacy browser SheetState, styled/typed cells, formulas stored in a workbook, imports, cooperative workbook editing, presentation, or HMC persistence.

Owner unit tests in formula.rs and PoetSnapshot native capability test are staged only, not executed; no Cargo command was run by this worker. The coordinator owns serialized builds/tests and dependency/lock changes. Audit independently reviewed the bounds and highlighted changed receipt semantics, WASM and lockfile risks; assess tests, return migration and resource accounting before installation.
