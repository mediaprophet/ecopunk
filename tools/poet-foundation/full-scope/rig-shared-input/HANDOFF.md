# Rig authoring to viewport resource handoff

Status: staged and source-reviewed only; no canonical files written, no Cargo or native test run. This is a bounded PA-01/02/rig authoring usability improvement, not a complete native human workflow or model claim.

Requirement and prior execution: the governing plan requires a native author to inspect, edit and present actual editable work with coherent selected source/part and exact HMC resource. The [prior signed synthetic GPU result](../../../../docs/qa/implementation-2026-10-27/full-scope-round1/rig-gpu-check.log) exercised `NativeProject -> AuthorizedEditorHost -> checkpoint resource selection -> InteractivePreviewProvider` with skeletal stepping and readback; it did not prove a human-operated window. Current `authoring/controls.rs` and `viewport_controls.rs` independently held filename, package digest, key and resource digest; the authoring panel falsely stated animated preview was not connected. The former required users to re-enter the same resource identity in a separate panel.

Candidate: `NativeStudio` owns one window-local set of user-entered fields. The authoring panel can explicitly copy key and resource digest from the current inspected bound rig into the viewport selection; it checks displayed source, selected part and current publication context. It does not infer package identity or authorization. The viewport requires the user to confirm the fields for the current full source/session/epoch/authority context, validates both digests and request bounds, synchronously compares context at preview dispatch, and also clears confirmation on field or context changes. The existing host still authenticates and checks exact package/resource digest and current selected geometry. Manual entry remains available. Descriptions call this manual preview/stepping, not continuous playback, and input controls receive accessible names.

Tests: `rig_resource_selection_tests::selected_rig_resource_requires_explicit_current_source_and_exact_digests` checks missing/current/foreign source, changed session revision and epoch, exact parsed digests and malformed/empty fields. This test is not execution evidence until run. The coordinator should independently review and install only after manifest preimage/hash validation, then run a nonzero filtered test, the native library regression and signed native GPU rig test under the serial guard. The UI itself needs a real native human interaction test; this staging does not establish it. The worker has not run a build, test, paid call, export or asset production.

Scope/limitations: input values are selections, not proof of access or resource identity; host admission and digest validation remain authoritative. Context changes invalidate preview confirmation but preserve text for user recovery. The existing selection check remains exact part-specific and rig descriptor-based. No new product schema, cross-repository engine or separate authoring app is introduced. The broader authoring families, animation and human usability remain open.
