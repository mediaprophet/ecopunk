# Surface package binding authority transaction

Staged only; no canonical changes, compilation or execution. The existing path is `AuthorizedEditorHost::bind_surface_package` -> shared owner -> optional `ResourceImportHost` -> `CheckpointEditorHost` -> `CheckpointService::surface_resources` -> canonical `install_surface_resources`. The service validates current source, bounded HMC bytes and digest before returning an in-memory `TextureResources`. Canonical installation replaces surface resources, retires the execution epoch, creates a successor and changes preview context. Existing signed native surface/UV tests first reject a bad HMC digest and then bind the correct digest on the same host.

The candidate holds the existing shared editor guard inside `ReadSource` authorization until outer owner/source checks return. A trusted typed `SurfaceBindingFailure` classifies pre-mutation preflight errors separately from possible mutation; unknown host errors default to possible mutation. Checkpoint preflight only reads and validates, and import decoration forwards that typed result. On refusal after actual or possible installation the whole shared host is quarantined under the guard; retiring only the frame would leave resources/epoch exposed. No rollback is claimed. Reconstruct and reconcile before retry. Nonshared/opaque hosts without the transaction capability fail closed. Custom raw hosts must not declare `BeforeMutation` after changing host state.

Eight staged CPU tests cover accepted binding, pre-dispatch denial, preflight refusal with retry, post-mutation error, duplicate callback, nonshared refusal, barrier-controlled outer rejection and a real checkpoint/canonical HMC binding with epoch retirement and owner rejection. These are source only. They do not establish native authority/GPU or human workflow; run focused, real signed native surface/UV cases, library regression and GPU checks before claiming. Existing global source-store access and arbitrary external effects do not become transactional through this lock. Source and prior files are pinned by the accompanying manifest.
