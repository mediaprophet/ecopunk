# Viewport representation identity candidate — staged only

Native authoring currently renders canonical source and disposable rig pose through the same retained source/epoch cache; the user-facing viewport labels both as source. This candidate distinguishes the two existing representations without introducing a botanical preview, a new source owner or a JSON format. `ViewportState` carries `Source` or an exact rig part/resource key/resource digest alongside its existing source, execution epoch and frame ID. `InteractivePreviewProvider` publishes the rig identity only after a successful pose, retains it through redraw/picking, and resets it when the viewport is retired or canonical source is restored. The existing native UI displays whether it is showing accepted source or a disposable rig pose. A monotonic, non-wrapping provider generation distinguishes Source→Rig→Source ABA. Pending/coalesced commands bind representation and generation; drag, pick and wheel interactions capture their generation and recheck after asynchronous layout.

The staged explicit GPU rig fixture asserts source→pose→source representation transition, frame identity changes and refusal of a stale pose pick after restoration. A pre-existing provider cancellation unit now also asserts representation retirement. The original two mock ViewportState constructors initialize `Source`. The stage was parsed with rustfmt only: no Cargo, GPU or UI tests were run. The focused GPU fixture may fail for pre-existing guard sequencing; diagnose rather than waive failures. The candidate does not produce botanical normals, expose a new Vibe capability, compile/save a derivative, change source/HMC, or qualify human usability. Source/epoch/frame checks remain necessary and no complete fork or botanical normal workflow is claimed.

Important limitation: current cache lookup remains keyed by source and epoch with a stored active representation. The only existing explicit replacement transition is `RestoreSourceGeometry`; adding an actual botanical derivative still requires a new authorized mode request, selected-part/profile identity in the cache key, a checked bounded geometry+UV mapping, publication/cancellation/revocation checks and stale-pick tests. The stage is a diagnostic and UI identity improvement for already-supported rig previews, not implementation of that unfinished geometry. Pointer drag captures the generation at mouse-down, and drag, wheel and pick callbacks recheck it after asynchronous layout. Frame-ID checks independently reject stale picks. The stage remains uncompiled and unexecuted.

`manifest.tsv` lists six exact canonical preimages and candidate SHA-256 pins. Parent owns all canonical installation, source review, serial Cargo and GPU execution.
