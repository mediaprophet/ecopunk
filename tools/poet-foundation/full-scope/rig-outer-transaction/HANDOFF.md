# Outer authorization retained viewport: staged candidate

Status: staged source only, uncompiled and unexecuted. The coordinator must independently review and preimage-check every manifest entry before installation. No canonical Poet file or Cargo process was changed by this worker.

The candidate adds a trusted accessor for the actual SharedEditorHost and acquires its existing try-lock only inside the authorized callback. That guard remains live through source checks, authority-owner return, duplicate callback detection and a final cancellation check. On failure, it retires the tentative viewport while still holding the guard; if the provider cannot explicitly confirm retirement, it quarantines the whole shared host because source submissions can also render through the same retained provider. Quarantine has no in-place recovery: reconstruct the host. Existing nonshared AuthorizedEditorHost viewport actions now fail closed rather than assuming atomicity. Successful publication linearizes at the final cancellation check under the guard; later revocation cannot retroactively revoke returned output.

The candidate forwards explicit retirement through CanonicalEditorHost, CheckpointEditorHost and optional ResourceImportHost. InteractivePreviewProvider confirms retirement using its existing invalidate implementation. The default provider and host retirement report failure, so no-op invalidation is not treated as proof. Four scripted tests exercise post-callback rejection with a concurrent frontend, failed retirement/quarantine, cancellation after callback and duplicate callback. These are fixture assertions only, not executed results, GPU qualification or human operation. Poison behavior follows the existing shared mutex refusal; native GPU and end-to-end contributor tests remain needed. Per-resource rights, memory bounds and UI delivery race remain separate concerns.

Manifest entries pin canonical preimages and candidates. Relevant existing paths include NativeProject composition and the authority and source-check path documented in SEAM.md; the source pins there are historical and should be rechecked. Additional automated review should check trait visibility, Rust guard lifetimes, closure captures, compatibility of intentionally refused nonshared viewport use, every shared rendering route, and host reconstruction behavior. Run focused `outer_viewport_transaction` tests plus previous rig and signed GPU tests through the serial disk guard, then rebuild only after actual successful results.

Recovery behavior: once inner dispatch has begun, an arbitrary error is not reliable proof that the GPU/CPU state was untouched, so the candidate conservatively retires it. The returned error explicitly asks the user to redraw and reselect. Existing `viewport_controls.rs` clears image, selection and viewport metadata on failed operations, stale completions and dispatch errors. The staged native GPU fixture now checks redraw/reselection after a stale pick and after a bad-resource refusal. Cancellation before authorization leaves state untouched. These tests remain unexecuted.

Scope: this transaction protects `viewport_action` calls through the shared/authorized host composition. Source `submit` and other mutation operations can invoke `preview_with_resources` via a separate source-write path; they are serialized while this viewport guard is held but their own post-authority publication is not established atomic by this change. UI delivery/current-context checks and external host compositions also remain separate.
