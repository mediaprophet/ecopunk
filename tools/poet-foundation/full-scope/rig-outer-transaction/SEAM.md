# Outer authority / retained viewport transaction: implementable seam

Status: source review and implementation design only, 2026-10-27. No canonical edits or tests. The companion post-publication handoff remains open. This design is not a claim of atomicity or production qualification.

## Existing ownership and lock trace

`NativeProject::open` constructs `CanonicalEditorHost -> CheckpointEditorHost -> optional ResourceImportHost -> SharedEditorHost`; each `connect` or `connect_selected` wraps a clone of that same shared host in `AuthorizedEditorHost`. `SelectedAuthorityOwner::with_current` holds selection, then delegates to `NativeAuthorityOwner::with_current`, which calls the native authority's serialized transaction and `source_transaction`. That transaction checks the actual source before and after the authorized callback. `with_authorized` performs current-document, admitted `ReadSource`, actual stamp/digest and post-operation source checks; it also refuses a missing or duplicate callback or an owner error. The current callback invokes `SharedEditorHost::viewport_action`, whose `current()` uses `try_lock` and immediately drops its guard on return. Thus the retained viewport may mutate before the outer owner/source checks finish. `CheckpointEditorHost::viewport_action` loads the selected resource then calls the canonical host; `CanonicalEditorHost` and `ViewportProvider` already invalidate their retained derived scene in their own post-check failure cases. These inner checks do not cover the outer interval.

Package-workflow paths use the existing authority/shared-editor transaction seam; shared acquisition is nonblocking (`try_lock`). `NativeProject::verify_package_target` separately takes the shared guard without acquiring authority itself, so callers must retain their own admission context. The selected-owner comment documents selection -> authority -> raw shared editor. Preserve this order; acquiring the shared editor before entering the authority transaction is not a safe piecemeal change. All current `SharedEditorHost` operations obtain the same `inner` mutex, so a retained guard excludes other participating frontends; inspect every newly added access path before assuming this remains true. `NativeAuthority` state mutex may block; that does not create a reverse-order acquisition in this design, since the shared lock is first acquired inside its callback.

## Bounded implementation (not yet applied)

1. Add an internal shared-viewport transaction capability to the existing host composition. `SharedEditorHost` must provide a cloneable handle to its same `Arc<Mutex<...>>`, not a new lock or copied viewport; expose the existing nonblocking guard only to trusted `AuthorizedEditorHost`. The outer wrapper must identify the actual shared host explicitly, e.g. a dedicated constructor used by all `NativeProject` connection paths, or a narrowly scoped trait accessor. Preserve `AuthorizedEditorHost::new` compatibility and do not silently claim that a nonshared host has this guarantee. Fail closed for a host lacking the required transactional capability if its retained state can be shared; update existing nonshared callers/tests deliberately.
2. In `AuthorizedEditorHost::viewport_action`, retain a local optional guard whose lifetime spans the *entire* `with_authorized` call. Inside its one admitted callback, acquire the raw shared guard with `try_lock`, store it in the outer local, and call the guarded **inner raw** `viewport_action` directly. Do not call `SharedEditorHost::viewport_action` while holding the guard: that re-enters the same mutex. The guard is therefore acquired only after selection and authority admission, stays held through `with_authorized` source recheck, native-owner post-source check, owner return and duplicate-callback checks, and is dropped only after accepted output or failure cleanup. Lock contention returns the existing busy refusal; no implicit retry.
3. On any refusal after the guard was acquired, retire tentative retained viewport state while still holding the same guard. Add an explicit internal retirement operation forwarding through the optional import and checkpoint decorators to the canonical preview owner. The provider contract must report whether retirement is actually supported; its current default `PreviewProvider::invalidate_rig_preview` is a no-op, so using that default as proof would be unsound. If retirement cannot be completed, quarantine the shared viewport under that same mutex and refuse future viewport reads/actions until an explicit verified recovery replaces or reconstructs it. Never release the guard with an unretired candidate visible. Poisoned state must also fail closed. Holding the guard rules out another accepted newer frame before cleanup; no unconditional invalidation after guard release is permitted.
4. Before successful release, check the operation's cancellation flag again; define successful publication's linearization point at the final checked transition under the shared guard. Preserve owner/source validation and output context; cancellation or source change after the authority transaction has already completed needs an explicit precise policy because independent Studio mutations are not automatically serialized by this guard. No guarantee should be made that revocation can retroactively revoke a frame already returned. The returned frame is still subject to existing publication/current-context checks at UI delivery.
5. Apply to every viewport action that can mutate or observe the retained scene, not only `RigPreview`; otherwise a concurrent redraw or selection could see the tentative candidate. Other shared-editor actions continue to use their existing try-lock behavior. Do not hold the guard across waiting for human input, automatic retries or unrelated background work. Track memory/resource and cancellation bounds separately.

Illustrative control flow (not directly compilable; retained guard lifetime and host capability types must be expressed safely):

```text
validate(command)
let mut guard = None
result = with_authorized(owner, scope, expected, ReadSource, |view, permit| {
    guard = Some(shared.try_guard()?);   // authority -> shared
    guard.raw_editor.viewport_action(command, expected, cancel)
})                                      // guard remains held through all outer checks
if result.is_err() or cancel_now {
    if guard exists and !guard.retire_retained_viewport(): guard.quarantine_viewport()
    return error
}
return result                            // guard drops after acceptance
```

## Deterministic validation before integration

Use barriers/channels, not sleeps. A scripted `AuthorityOwner` calls back once, waits at a barrier after that callback and returns an error. A second authorized frontend attempts redraw while the first is paused: it must receive the busy refusal and cannot observe the candidate. Release the first, verify retirement or quarantine before guard release; then permit a successful newer redraw and verify it is never discarded by delayed cleanup. Complement with successful candidate publication; duplicate callback (operation runs once, no candidate exposed); owner rejection before and after callback; source retirement during callback; cancellation before dispatch and after inner callback; lock contention; selection/session disconnect; poisoned shared state; retirement failure and explicit recovery; nonshared host behavior. Prove current permit and exact-source checks remain effective. A scripted owner is only concurrency evidence for this seam. Separately run the mounted signed NativeProject GPU fixture and later a real native contributor workflow; neither source inspection nor a CPU mock proves GPU or human interaction.

The coordinator should create a staged patch with exact source hashes for `editor_contract.rs`, `shared_host.rs`, `cooperation/editor.rs`, `cooperation/mod.rs`/`native_project.rs` as chosen, `checkpoints/editor.rs`, `package/mod.rs`, `controller.rs`, preview provider and disjoint deterministic tests. Review borrow/lifetime behavior and all raw viewport accessor paths before installation. Keep the current rig GPU check and user-requested build tied to their own declared snapshot. Capture actual check results and do not mark this gap closed on compile alone.
