# Workbook P0 checkpoint and cooperative host staging

Status: staged only, uncompiled and untested. This adapts Poet's existing selected HMC/checkpoint and native authority owners to the bounded `graphical::workbook_p0` GridCraft-session profile; it depends on the separate engine candidate and is not a standalone adapter, full workbook editor, XLSX/ODS support, provenance verification or human acceptance.

## Existing owner and behavior

`checkpoints/inspection.rs::read_selected_resource` and `typed_10d/service.rs` demonstrate current live SourceRef/stamp, bound document, source digest, HMC path/package digest, resource digest, release policy and bounded payload checks. `checkpoints/resources.rs::save_with_resource_edits` uses a retained canonical carrier, exact existing package digest and `ResourceEdit::ReplaceBytes` to preserve unrelated resources/metadata. `cooperation/editor.rs` uses `with_authorized(ReadSource)` for inspection and `write_package` with existing `SaveCheckpoint` and `PackageWriteIntent` for resource edits. `shared_host.rs`, `package/mod.rs` and `session_host.rs` are the native shared/import/reconnecting decorators. These are implementation patterns, not a claim that a source digest establishes permission, rights or provenance.

## Candidate and limits

`WorkbookCreateRequest` creates a blank bounded profile in an existing exact HMC and never overwrites a resource. `WorkbookEditRequest` identifies the exact HMC and resource SHA plus explicit Sheet1/cell/input; the detached GridCraft session in the engine candidate owns parsing and calculation. `WorkbookInspection` returns the checked request, saved artifact revision and actual bounded view. Read/edit refuse unknown kind, metadata-bearing workbook resource and payload beyond 128 KiB; unrelated resources and metadata are carried via the existing checkpoint owner. Original XLSX/ODS imports and formulas are not supported. Profile bytes are data, not proof of origin, provenance, adopted rights or authorization.

Create/edit use the existing package-write authority; inspection requires ReadSource. Observers cannot write; revocation is checked by the outer owner. Cancellation is checked before and after decode/replay and immediately before checkpoint save. The existing atomic checkpoint save does not accept a cancellation token; cancellation after entering that call cannot be promised to roll it back. Existing portable external-writer and power-loss limits remain. Numeric saved source revision is not assumed to equal UI session revision; host source stamp and canonical source digest must match. Resource digests identify exact content, not referents or roles.

Two staged tests exercise a real HMC create/edit/reopen with preserved unrelated opaque resource and refusal on stale digest, formula and prior cancellation, plus a software-agent authority fixture showing observer read / denied write and revocation. Neither has been run. A selected resource's HMC full-file load remains governed by existing CheckpointLimits, not the 128 KiB profile cap; the aggregate allocation behavior needs measurement. Source file/candidate hashes and absence pins are in the manifest. A signed NativeProject, actual native human interaction, persistent shared workbook session and cooperative review remain unqualified.
