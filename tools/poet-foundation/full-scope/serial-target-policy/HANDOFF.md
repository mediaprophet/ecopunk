# Serial native-check shared-target policy — staged

## Observed collision

`qualia-core-db/Cargo.toml` sets `crate-type = ["rlib", "cdylib"]`; in this Windows target the library artifact is the un-hashed `target/debug/deps/libqualia_core_db.rlib`. The separate Poet and Qualia/MCP Cargo graphs have distinct Core fingerprints and dependency identities but use that same filename. The Qualia/MCP run overwrote it after the Poet fingerprint was recorded, and the later Poet build reported mismatched Vibe, bytemuck and Etalon types. A serial lease prevents overlap, not sequential cross-graph overwrite. The coordinator is repairing the existing target separately; this candidate does not repair it or delete anything.

## Staged policy and compatibility

The existing helper still uses the same native-check lease, 30 GiB start guard, running disk budget, environment defaults and sole target. Before starting Cargo it requires cwd `C:/github/poet`, exactly one selected package `poet-cli`, exactly one feature argument `native-graphical`, the existing shared target and locked/offline build/check/test. It allows the historical explicit `--manifest-path C:/github/poet/Cargo.toml` and normalized equivalent, and rejects another manifest, extra feature selection, `--config`, `--all-features`, `--no-default-features`, workspace/all/exclude options, repeated target/manifest and other workspaces with explicit actionable errors. Cargo test arguments after `--` are left intact. No cache or executable is removed.

This is an intentional compatibility restriction: older `human-authority-round1/run_check.py` and `post-update-qualification/run_check.py` wrappers accepted both Poet and Qualia workspaces, and their Qualia invocations against this target will now be refused. Poet invocations from an Ecopunk cwd or Poet native subdirectory, non-root manifest paths, other features/packages and `cargo clean/run/rustc` are also refused. To run Qualia Core or Qualia MCP checks, a separately designed serialized, disk-guarded isolated-target workflow is required; this helper currently accepts no other target and does not automatically provision or approve one. This tradeoff prevents the known cross-workspace overwrite rather than silently relying on the lease.

The restriction protects cooperating invocations of this helper, not direct/unrelated Cargo processes. It is not a product security gate. Even in the same workspace, inherited `RUSTFLAGS`, toolchain or Cargo config, Cargo target-selection/dev dependencies, and external filesystem writers can change compilation identities; the policy is not a proof that every same-workspace graph is identical. Environment/profile isolation and noncooperating builds need additional qualification. Do not install the candidate while a check uses the lease; wait for owned process completion and preserve any intervening source changes.

## Validation

The staged `test_serial_target_policy.py` imported the candidate and a byte-identical staged copy of the existing disk-budget module. On 2026-10-28 it passed 4 standard-library unit tests covering standard Poet build/test command forms, `--manifest-path` and path normalization, alternate workspace/package/feature/target rejection, explicit errors, duplicate options and required locked/offline flags. It did not start Cargo, acquire the real lease or test disk behavior. These are parser tests only and do not verify an end-to-end build or prevent bypass. Exact source/test hashes and source preimage are in [manifest.json](manifest.json). No canonical files were changed by this worker.
