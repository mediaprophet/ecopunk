# Staged UV-split normal transfer

This is an unintegrated candidate; no tests, builds or canonical source edits were performed. It provides a narrowly useful implementation seam, not a complete junction-authoring solution.

Existing `qualia-core-db/.../computational_geometry/uv_atlas/mod.rs` (`SHA-256 59dfc1333ed9daab1737bfe66381f95f11ea1524df514dab179fcc9696c52022`) accepts explicit seams, cuts disk charts, emits `source_vertices`, preserves triangle order/winding, and validates the delivered f32 UVs against fold and overlap. It intentionally makes UV cuts, does not claim distortion/conformality limits, and cannot automatically parameterize arbitrary closed forks without appropriate authored seams. The existing area-weighted `ddg_operators::vertex_normals` (`SHA-256 6897089ebde2e21c6b3b94e3e0ea22a8cc046af74894cdb015123606e26fddb4`) operates on a mesh; if run after an atlas split it can produce different normals on copies of the same original vertex. `hard_cap_sweep.rs` already reuses this kernel for a distinct render derivative and treats caps specially.

The staged module computes the existing normal kernel on the original indexed surface and maps those normals to atlas split vertices. It validates the atlas-to-source corner mapping and checks each face's squared cross-product against a caller-selected minimum in m⁴, refusing zero, under-threshold or nonfinite results before publishing output. It provides bounded scratch and work admission, and leaves output unchanged on failure. Candidate tests cover shared source normals across a cut, invalid correspondence and budget, and zero-area faces including one adjacent to a nondegenerate face. Source review and actual tests are outstanding. The numerical checks do not certify normal accuracy at extreme scales. This is a smooth-only derivative: it intentionally cannot represent artist-authored sharp normal groups, does not generate a tangent stream or establish UV continuity through atlas seams, and does not preserve existing authored UV/normal streams on a remesh. All those require explicit author decisions and source representation.

Potential integration after independent review: install `atlas_source_normals.rs` into the Core computational_geometry module, add `pub mod atlas_source_normals;` in its owner `mod.rs`, and call only after a successful existing atlas unwrap using exact slices from its result. Charge its work and scratch in the same host-selected operation budget as the field, topology and atlas; this module's `3*vertices + 12*faces + 3*split_vertices` counts structural passes with conservative per-face weighting, not CPU instructions or a complete budget for the full transaction. Do not publish partially generated output on error. Do not overwrite the master, existing UVs, normals or skin data, and do not present this result as a qualified biological asset or seamless texture painting workflow.
