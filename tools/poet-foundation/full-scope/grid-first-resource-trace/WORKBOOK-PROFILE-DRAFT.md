# Proposed PA-08 workbook resource profile and acceptance plan

**Status:** requirements-first draft for implementation review; not an adopted format, released specification, executable adapter, grant, waiver or completed PA-08. It is prepared from the [refreshed owner trace](HANDOFF.md) and [specific source pins](source-pins.json); those pins are not a complete dependency or semantic audit. Existing Ecopunk [PA-08](../../../../docs/planning/tech/poet-comprehensive-authoring-review.md) and the [governing implementation plan](../../../../docs/planning/implementation-plan.md) remain in force. Design choices marked open below cannot be treated as accepted merely because this draft names them.

## Target operation and existing seam

A person or separately authorized agent selects one workbook associated with the current native Poet project and exact source/package/resource revision, enters a cell value or formula, sees the recalculated result and any refusal, then saves and reopens the same editable work. Use GridCraft's existing `Session::execute("cell.set", ...)` for formula parsing, protection and undo/recalculation; use the existing native Poet authority owner, source stamp, checkpoint edit/save owner and shared session rather than a private workbook authorizer or parallel UI state. The runtime must not require JS/V8. The QualiaDB numeric-grid `Sheet` functions are related existing operations, not a proven substitute for the workbook engine or its formula semantics. A workbook is an authored document; its cells do not automatically become Q42 claims, rights, agreements, payments or authority.

The first implementation should cover one bounded native source-to-output slice. It must not claim all PA-08: units, charts, range behavior, accessibility, cross-format import/export, WASM and human review continue until separately demonstrated.

## Proposed profile P0 — requirements, not an adopted HMC kind

P0 is a proposed *bounded editable native workbook derivative*, backed by a versioned, explicitly admitted schema and an associated original-source record where one exists. Do not select a production MIME string, HMC key, UUID scheme, extension-based authorization or wire schema until the owning host/domain review assigns and pins them. A native newly created workbook may have no imported file; represent that fact explicitly rather than fabricate one. Retain the original imported XLSX/ODS bytes as a separate inert, digest-addressed source resource, never overwrite or reinterpret them as the editable derivative. Record their actual origin, review/rights status, and any import loss report as evidence, not as a grant.

Each editable derivative must carry, or be bound by verified host-owned records to:

1. A profile identifier and schema version with exact compatibility behavior. Unsupported/newer versions fail closed for editing; optional opaque unknown data remains byte-exact or the edit is refused. Do not silently accept a serde field that would disappear during serialization.
2. Project/source/workbook identifiers with their scheme/scope, the selected HMC resource key/kind, exact source stamp and package/resource SHA-256s, and a session/workbook revision. Distinguish identity from digest and observed author from authenticated authority; digest equality is not authorization or referent equivalence.
3. An authored workbook model preserving cell types/formulas, sheets, protection, names, formatting, relevant units/labels and other admitted profile features. Model and engine versions and the exact compatible dependency/provenance closure are pinned; original notices accompany reused MIT-licensed code. Unsupported features and export losses are listed explicitly. Do not imply full XLSX/ODS round-trip support from a limited profile.
4. Provenance linking a derivative to original exact input bytes and import report, or an explicit new-native origin; package/adoption/rights/review states remain distinct. Preserve unrelated HMC resources and their opaque metadata on a cell edit.
5. Explicit finite limits for compressed/input bytes, aggregate decoded bytes and archive entries, nesting/depth, sheets, stored cells, individual and aggregate text/formulas, formula dependency graph/work, recalculation time/work, undo/journal history, output bytes and cancellation checks. The host chooses and records a concrete approved limit profile. Existing GridCraft ZIP part/total/entry and ODS limits are starting points, not proof that aggregate application memory or recalc work is bounded. No placeholder numeric value in this draft is an approved production budget.

Open design choices to resolve with the responsible implementation owners: exact schema/codec and explicit kind; GridCraft distribution/dependency closure and license notices; whether strict native model decoding can validate all nested unknown content without loss or requires a different versioned representation; stable workbook/sheet/cell identifier and unit mapping; owner-selected budgets; supported import classes and per-feature loss policy; cross-process undo persistence; exact delegated-action capability/role mapping using existing policy; GUI/agent session sharing and recovery semantics; dynamic-spill admission; normalization/raw-input retention; and volatile calculation context, cache and reopen policy. These are technical implementation decisions; none requires a new user confirmation merely because it is listed here.

## Initial command and evaluation semantics — proposed P0 boundaries

**Explicit single-cell operation.** The first cell-entry slice accepts an explicit, validated workbook, sheet and cell and an explicit string input, and invokes `cell.set` with `array: false`; it does not expose legacy array entry. Empty string is allowed only as an intentional explicit cell clear, not as a fallback for missing input. Validate a syntactically invalid/missing cell and sheet *before* engine dispatch; the current `cell.set` implementation falls back to the session's active selection when no cell parses and defaults missing input to empty. Its `array: true` branch uses the current selection and can clear other cells. A malformed or incomplete agent/human request must not unexpectedly edit the active cell or selection. A single authored target does not imply recalculation has only one observable result: dependent values or dynamic array spills may affect other cells. P0 must explicitly define supported spills and protect every affected cell, or refuse a candidate whose spill/protection/preservation behavior cannot be established; do not silently truncate or treat spill work as authorized bulk editing.

**Input normalization and errors.** Preserve the exact user-entered input alongside the engine-accepted canonical cell/formula representation whenever the adopted profile requires source fidelity; at minimum surface any normalization before commitment or retain an auditable conversion record. The inspected `input_to_cell` can parse format-dependent text/numbers, add automatic formatting, and try up to eight closing parentheses while parsing formulas. A normalized valid formula is not identical evidence to the original text. Distinguish (1) rejected parsing/invalid request, which must not commit a candidate; (2) accepted formula whose calculated result is an error value such as divide-by-zero or unsupported reference/function, whose persistence and presentation policy needs an explicit profile decision; and (3) valid literals including an intentional empty cell. Do not call a calculation error a parser failure or silently convert an error value to zero/blank. Proposed default pending owner review: admit only formula/error classes with defined, tested persistence and display semantics; otherwise withhold the candidate without damaging the original.

**Volatile evaluation and reopen.** Formula text and a saved workbook do not by themselves guarantee reproducible results for volatile functions. The inspected GridCraft `Calc` has a mutable pseudo-random state and optional fixed time (`None` reads the system clock); `DocState::new` constructs a new `Calc` and runs `recalc_all`. `NOW`, `TODAY` and `RANDARRAY` are marked volatile in the inspected function registry. Therefore the profile must decide whether to refuse unsupported volatile formulas or admit them under an explicit evaluation context and cached-result policy. If admitted, pin engine/function versions, clock instant and timezone/date-system interpretation, randomness seed/state and evaluation/recalculation order or an equivalent proven deterministic context, and declare whether reopen preserves cached values or recalculates. Record actual context/provenance and distinguish reproducible replay from an intentional live refresh. A seed alone is not proof of reproducibility; dependency traversal, external inputs and clock handling must also be qualified. Persisted formula source, result cache and evaluation context are distinct. Do not claim same results after fresh-process reopen until the chosen behavior is implemented and tested.

## Guarded operation lifecycle

**A. Admission.** Under current `ReadSource`/appropriate editor authority, check current project/source, exact file/path policy and expected HMC digest, selected resource key/kind and exact digest, schema/version, metadata/provenance and declared rights. A selected filename, caller-supplied actor or resource digest alone is not authority. Reject unsupported/encrypted/unknown/lossy content for the requested edit before changing accepted package/session. Preserve immutable original resource bytes and report any conversion/loss without assigning review approval.

**B. Prepare bounded candidate.** Validate input sizes, schema and unknown-field policy *before* admitting the workbook model. Build a bounded candidate session from the exact admitted revision, with explicit cancel/work budgets and memory accounting that include decompression, allocation, recalc, history and output. `read_selected_resource` is currently 10d-specific, so reuse its owner/source/digest/revalidation pattern through an appropriate profile-specific public seam; do not weaken existing 10d checks. Any proof that candidate creation/serialization preserves all accepted fields must be based on executed semantic tests, not a matching file hash alone.

**C. Edit.** Under existing action/role policy, invoke the same `cell.set` domain operation for human and agent, using a validated explicit sheet, cell and string input with legacy array mode disabled. Recheck expected source/session/resource revision immediately before the commit. Perform this on a detached candidate or a demonstrated equivalent transactional owner: GridCraft catches panic and restores its workbook, but the inspected `Session::execute` does not establish that *every returned error* rolls back all intermediate mutation, nor does it establish native authority. A failed/cancelled candidate must never replace accepted workbook state or package. Concurrent successful edits use explicit conflict/refusal semantics; never retry or overwrite without an authorized current revision.

**D. Validate and commit.** Verify the resulting admitted profile, loss report and bounds, preserve untouched resources and provenance, then call the existing checkpoint owner with expected source stamp, expected package digest and expected old resource digest (`ReplaceBytes` where its preservation semantics fit). Keep the authority/serialization owner through the actual install. Determine cancellation's linearization point: before install, refuse without package change; after successful atomic installation, report the actual result and do not claim rollback. Qualify the checkpoint's external-writer and power-loss limits instead of asserting stronger guarantees.

**E. Present and recover.** Native Poet exposes the real selected sheet/cell, formula input, computed value and refusal state through the existing workspace/intent and worker model. Human and agent edits map to that same session owner. Reopen a saved HMC in a fresh process, validate provenance/profile, restore the exact admitted editable workbook and explicitly define which undo/history survives. A local cell rendering, synthetic agent test, source test or exported file is not evidence of human acceptance.

## Acceptance and verification matrix

| ID | Setup and exercised behavior | Required observable evidence |
|---|---|---|
| WB-A01 | Profile owner chooses concrete schema/version, budgets and dependency/license pin. | Reviewable contract, full source/dependency/provenance identifiers and no silent adoption of draft. |
| WB-A02 | Authenticated exact source/package/resource; supported minimal workbook. | Actual mounted Poet session and cell projection; same data/revision for permitted human and agent routes. |
| WB-A03 | Enter literal and formula through `cell.set`, including dependent cell and re-evaluation. | Actual returned values, formulas and revisions; no UI-only fabricated state. |
| WB-A04 | Protected sheet/cell, denied actor and disabled operation. | Explicit refusal; no change to source, model, package or unrelated resources. |
| WB-A05 | Unknown schema, unknown nested field/feature and unsupported formula/import. | Safe explicit refusal or demonstrated byte-exact preservation plus loss report; original bytes unchanged. |
| WB-A06 | Oversized compressed input, expanded entries, cells/text/formula graph/recalc and output at limit and one over. | Bounded measured execution or refusal before unsafe allocation; no partial commit. Include exact observed budgets, not placeholders. |
| WB-A07 | Stale source stamp, source/session revision, package digest or resource digest; two competing writers. | Stale request fails; accepted winner remains exact; no automatic retry or conflict erasure. |
| WB-A08 | Cancellation during load, decode, calculation and immediately before commit. | Measured no-change behavior where pre-install; actual result after install; no false rollback. |
| WB-A09 | Changed cell with unrelated Q42/unknown resources and original workbook source in HMC. | Exact bytes and metadata preserved; derivation/review/rights remain qualified. |
| WB-A10 | Undo/redo and restart/reopen using fresh process. | Explicit persisted vs session-only history behavior and correct formula/value/source/resource versions. |
| WB-A11 | Hostile/malformed inputs, corrupt files and unsupported encryption. | Fail closed with diagnostics and no false materialization/acceptance. |
| WB-A12 | Select, edit, conflict and recover via native human workflow; independently authorized agent repeats equivalent operation. | Actual operator and independent human review evidence; local API, synthetic fixture or source presence alone is insufficient. |
| WB-A13 | Native/WASM binding and declared export in separately qualified target profiles. | Exact target, dependencies and allowed loss report; no required JS/V8 for native path. |
| WB-A14 | Missing/malformed explicit cell or sheet, omitted input, explicit empty input, requested array mode and dynamic spill into protected/occupied/out-of-profile cells. | No implicit active-selection edit or accidental clear; explicit empty clears only the intended target; array/spill handling matches the adopted profile and preserves unrelated cells. |
| WB-A15 | Formatting-sensitive input, auto-closed or otherwise normalized formula, unparseable syntax, and an accepted formula producing a calculation error. | Original vs accepted representation and conversion are visible/preserved per profile; parsing refusal cannot commit; an admitted calculation-error value is preserved/displayed as an error, never silently zeroed. |
| WB-A16 | Volatile date/time and random formulas under fresh session, repeat, save/reopen and deliberately changed evaluation context. | The adopted context and cache/recalculation policy is explicit and pinned; reproducible cases match under the same qualified context, changed/live cases report the difference, and unsupported volatility is refused without source loss. |

Coordinator owns canonical shared source and serial guarded Cargo/GPU checks. Before dispatch, verify working preimages and old evidence; workers stage disjoint files with manifests. First implementation PR-sized slice should establish and test an approved profile and admitted read path, then demonstrate the actual authorized edit-and-reopen vertical slice; a read-only envelope alone is not a finished spreadsheet product. Track source-present, compiled, executed, native-rendered and human-accepted evidence separately and do not close PA-08 on a single fixture.
