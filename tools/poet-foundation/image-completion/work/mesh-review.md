## Diagnosis

The failing test creates two `MeshService` threads with 500 ms UDP read timeouts, completes command-based peer setup, initiates A's handshake, waits up to 10 seconds for A's session, then sends A-to-B and waits up to 10 seconds for B's inbound packet. It does not explicitly verify B's session before sending; the neighboring synchronous mesh test at `social_webnet.rs:267-278` pumps B again and checks B's session. A successful `send` reply means the local tunnel emitted a UDP datagram, not that B received it. The service thread drains commands, calls `pump_all` (which can block on each socket timeout), forwards successful packets, and ticks timers. It drops per-peer pump and timer errors at `mesh_service.rs:331-345`. `MeshControl::request` and `MeshService::request` have unbounded reply waits. The final panic narrows the failure to B's receive path, but does not distinguish scheduling delay, datagram/crypto loss, or an error discarded by the service loop. The passing lower-layer tests establish that the socket and tunnel paths worked in this run; they do not prove this threaded path.

The coordinator's isolated execution of the same compiled test binary passed: `docs/qa/implementation-2026-10-26/image-completion/mesh-isolated.log` and `mesh-isolated-result.json` report one passed test, exit code 0, in 3.60 seconds with one test thread. This rules out a reliably reproducible failure on that binary. It supports full-suite timing or interference as a hypothesis, but one isolated pass cannot identify which or prove the service path is robust under load.

Minimal next step is focused observation of B's `pump_all` outcomes and session state during a loaded reproduction, ideally using the existing test binary with controlled parallel test pressure. If a per-peer error occurred, report and fix that operation. If B remained idle despite the sent datagram, inspect service loop responsiveness and the socket path. The test's `#[serial_test::serial]` prevents overlap with the serial group only; it does not exclude unrelated parallel Core tests. Preserve the end-to-end delivery assertion; no timeout increase, skip, or source change is justified by the current evidence alone. Keep this failure separate from the 15 image cases.
