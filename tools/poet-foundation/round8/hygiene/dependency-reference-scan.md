Date: 2026-10-26. Read-only follow-up to the [Round 8 hygiene report](../../../../docs/qa/implementation-2026-10-26/round8/hygiene-report.md). No staged file was run, edited, or moved.

## Findings

- The 733-file map covers seven rounds: 649 Rust files, 19 Cargo manifests/locks and 65 Python/PowerShell scripts. The 19 Cargo files are staged before/after/installed Poet manifest snapshots, not self-contained harness manifests; they include absolute sibling paths under `C:/github/qualiaDB` and `C:/github/rust-app-framework`, plus Poet-relative paths. Do not treat them as independent workspaces.
- Eight `run_*.py` scripts invoke Cargo against live sibling workspaces or Ecopunk's WASM check manifest, writing logs/receipts and using `target` scratch. The Round 6/7 sequence scripts invoke sibling `run_check.py` files. Seven `verify*.py` scripts were identified. Round 1's verifier reads result/log files through `HERE` and has a production asset output path; Round 3–7 verifiers also read receipts relative to `HERE`. These files will move while their un-mapped JSON/log/image evidence remains in `docs/qa`. Thus direct execution of the moved verifier scripts will not find its old evidence directory. The verifier scripts read unmoved evidence relative to `HERE`, and pin manifests contain absolute old stage paths. Neither direct replay nor replay through a path-context shim is qualified. Treat all moved scripts as archived historical source, not runnable entrypoints; do not rewrite or rerun them as part of relocation. Cargo runners remain unexecuted and must not be used as relocation checks.
- Round 7 preparation scripts check `PREPARATION-FROZEN.json`; historical staging/install scripts are not replay producers. Their target paths or generated results may reach live siblings. No preparation or install script is run by this scan.
- No Rust `#[path]`, `include!`, `include_str!`, or `include_bytes!` directives were found among the 649 mapped Rust files. Normal Rust modules use sibling paths. The proposed mapping preserves the full `roundN` subtree and ancestor depth, so `Path(__file__).parents[5]` / `[6]` root calculations are preserved when an archived source is invoked with its original logical `__file__`.
- The comprehensive ripgrep pass built 8,154 exact-file and containing-directory path patterns for all 733 entries. Excluding `.git`, `target`, and this hygiene workspace, it returned 176 lines overall: 154 exact-file path matches and 22 directory-only path matches. Exact-file references occur in 23 non-mapped round files, mainly source/install/review pin manifests and preserved diff files. They are historical path-bearing evidence and should remain byte-identical; the proposed migration index supplies original-to-archive resolution. A moved-file reference scan against Markdown alone returned zero exact-file matches.
- Six active Markdown documents had round-evidence mentions during the earlier broad link scan. Their targets are retained Markdown/JSON evidence records, not mapped code files, so their links remain valid and no link changes are safe or needed. [active-markdown-afterimage-review.json](active-markdown-afterimage-review.json) records the six exact source hashes and no-change disposition; no afterimages were fabricated.
- Other `docs/qa` code/script/manifest cohorts, excluding `target` and the seven mapped rounds, total 732 files / 15,960,829 bytes: `implementation-2026-10-24` has 363 files / 11,820,769 bytes; `implementation-2026-10-25` has 369 files / 4,140,060 bytes. Non-round batch-6 cohorts include `assembly`, `craft/originals`, `ui-before`, and `authoring-tests-before`; archive/cleanup decisions for them need their own scan.

## Relocation implication

The destination layout preserves relative module paths and repository-root depth, but not the `HERE` location expected by old verifiers. Their evidence remains under `docs/qa`, and path-bearing receipts also retain old source locations. Treat every moved script as archived historical content, not a supported runnable entrypoint. Preserve receipts byte-for-byte and use the read-only [archived-path resolver](resolve-archived-path.ps1) against the migration index. The relocation script remains unexecuted and requires explicit `-Apply`.
