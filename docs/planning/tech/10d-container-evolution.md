# `.10d` evolution for exceptional Ecopunk production

**Status:** proposed requirements and qualification roadmap, 2026-10-25.
This is not a released format revision, a universal superiority claim, or evidence
that the listed capabilities work together. The [implementation plan](../implementation-plan.md)
still governs delivery. The user's subsequent foundation-first instruction is
recorded in [the format/SDK gates](format-sdk-foundation.md): qualify the ecosystem
foundations before resuming asset production. Existing reference outputs are
regression inputs while that hold applies; they do not set the master quality
ceiling or authorize new production work.

## Aim and boundaries

Develop `.10d`, its native SDK and Poet authoring into a demonstrably better
combination for high-grade, knowledge-linked, cooperative production and delivery.
Compare identified releases and declared workflows. A file can have more features
while losing on loading time, precision, interoperability or usable authoring;
each comparative claim therefore needs its own evidence.

HMC remains the complete embodiment container: available species/thing knowledge,
editable sources, resources, provenance and reviewed representations belong there.
`.10d` supplies typed representations/resources within that embodiment. Do not
create a second authoritative graph, project, rights or payment system in `.10d`.
Use identifiers with qualified associations; local part keys and digests have
separate roles and do not establish authority or universal equivalence.
Precision, style, LOD, biological state, simulation fidelity and delivery target
remain separate dimensions. A depiction change preserves its referent and state.

The current inspected representation uses a version-2 container and a quantized
mesh with `u16` coordinates in an `f32` bounding frame. It is a delivery derivative,
not a ceiling on editable master fidelity. The current numeric correction is
specified in the [Core QuantizedMesh companion](C:/github/qualiaDB/docs/manuals/standards/10d-container-format.md).
It changes decoding arithmetic and malformed-frame rejection, not encoded bytes
or the container version.

## Reuse before extension

The [bounded source audit](../../qa/implementation-2026-10-25/batch-6/rounds/round1/producer/format-evolution-audit.json)
records 12 areas with source/API, wiring and execution evidence separately.
Existing code includes typed materials, normals/tangents, UVs, skeletal clips,
morphs, manifold/field manifests, provenance, procedural descriptors, spatial
indexes and several dense/sparse representations. Their presence does not prove
joint packaging, native editing, rendering or interchange. Qualify the existing
owners before adding replacement sections or codecs.

The first growing-station HMC retains source edits and a 199-part derivative.
Its initial fresh-process regeneration reproduced the exact `.10d` bytes, then
exposed the endpoint-decoding defect. That scope does not qualify complete part
knowledge, human acceptance, film/game/cartoon delivery or all existing sections.

## Comparison contract

Use named versions, the same source assets, compatible quality settings and
properly configured competing implementations. Relevant baseline strengths include:

- [glTF](https://registry.khronos.org/glTF/) for runtime asset delivery, including
  its [registered extensions](https://github.com/KhronosGroup/glTF/tree/main/extensions).
- [OpenUSD](https://openusd.org/release/intro.html) for production composition,
  layering, overrides and assembling assets into scenes.
- [MaterialX](https://materialx.org/Specification.html) for material interchange,
  physically based and non-photorealistic shading descriptions.
- CAD/manufacturing, baked-geometry and sparse-volume interchange cases selected
  against the actual assets and production requirements; extend the census when
  a required workflow is absent. These are separate benchmarks, not interchangeable
  file types with one universal winner.

Measure fidelity/precision, semantic retention, edit/review/recovery success,
dependency preservation, load/update cost, memory, transfer size and actual native
rendering. Keep authoring, interchange and delivery profiles separate. Record
hardware, versions, input/output digests, commands, failures and independent review.
Set numerical targets from the reference cases before claiming an improvement;
no comparative performance or quality win has been established by this roadmap.
