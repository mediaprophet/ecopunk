## Routing, cost and concurrency

- Use the lowest-cost **capable** model based on the session's available capability descriptions, not an assumed rate: **gpt-6-luna** for bounded metadata, notice, inventory and mechanical changes; **gpt-6.1-sol** medium for an isolated implementation with a stable contract; Sol high for native UI, domain state, authority/session work, integration or independent review. Use **gpt-6-astra** only after the worker/coordinator records a specific unresolved architectural question and the evidence a stronger review must resolve. Model choice never reduces the acceptance evidence.
- Record the model and reasoning effort actually used, retries, completed outputs, and usage/cost metrics only when available. Mark missing metrics unknown; do not report estimated hours, token totals, dollar costs or model savings as fact without comparable measured work. Include coordinator and subagent work, retries, and applicable tools/compute. OpenAI's [multi-agent guidance](https://developers.openai.com/api/docs/guides/agents-api/multi-agent) recommends delegating independent tasks with clear outputs and keeping dependent steps in the main agent; its [observability guidance](https://developers.openai.com/api/docs/guides/agents-api/observability) says recorded usage is best-effort and not a final bill. These are planning references, not cost guarantees for this workspace.
- Maximum capacity is four concurrent agents total, including coordinator. W1 is normally coordinator plus one or two workers because model/control/history integration contends. W2 and W3 can use up to three workers only with frozen contracts and disjoint canonical files. W4 is coordinator plus one independent reviewer; use fewer if review requires source changes. Root alone owns shared manifests, controller/registry changes, integration decisions and the serial Cargo check lease. Workers do not run Cargo or start duplicate workspace builds. No source edits during coordinator checks.

## Assignment and handoff contract

Before dispatch, coordinator writes each worker's short task with:

1. Existing IP/ECO/PA/BS/R IDs and one specific human operation plus the matching agent operation; cite the existing requirement and actual Poet/QualiaDB caller example.
2. Exact repositories, immutable input pins, owned output paths/symbols, explicit non-owned paths, dependencies, and expected handoff artifacts. Never assign overlapping canonical files. Use isolated worktrees or staged patches and preimage hashes; source siblings stay read-only absent separate authorization.
3. Observable acceptance cases: expected document/source state, authority and revision, preview/result, undo/redo, save/reopen, failure/refusal behavior, and evidence owner. Separate source presence, implementation, executed result, domain review and human acceptance.
4. Allowed commands and who runs them; selected model/effort with a task-based reason; measured usage or `unknown`; stop condition and next owner.

Handoff records job/status, model/effort, source preimages and changed-file hashes, outputs, decisions, command/session/exit (or not run), actual logs, check state, failures, open IDs and restart action. Do not infer progress from a report count or missing output. If a contract or permission is unclear, stop that dependent slice and hand back the exact question while independent work continues. On a concrete failure, capture the reproducer once and repair only owned scope; after one focused repair fails or the same failure repeats, stop repeating that approach and escalate to the coordinator with evidence. The coordinator repairs or re-scopes the cause; the dependent gate remains failed until resolved. Astra escalation requires the specific unresolved question. No worker may self-accept an asset or grant itself reviewer authority.

## Restart and status

On resume, read repository instructions, the current working tree/process/check lease, this plan, the relevant packet and applicable adaptation/native contract. Preserve dirty work; verify preimages and running-child state before continuing. Reuse completed evidence unless an input changed or a failure calls for a targeted rerun. The coordinator records the exact next operation and current ownership in the existing handoff/register; this document does not dispatch jobs or edit the central register.
