# Qualification, quality benchmarks and complete delivery

28 October 2026. Planned acceptance and evidence contracts, not executed tests. Follows [critical path](00-critical-path.md), existing IP/FND gates and the [model-completion contract](../tech/assets/model-completion-claims.md).

## Define excellence for the case before judging it

Pin reference evidence, intended use, source availability and comparison baseline for each subject/place. Evaluate anatomical/geographic correctness, editable structure, material/lighting fidelity, movement/contact/sound, knowledge and inference usefulness, native usability, recovery and measured resource cost. A superior result must demonstrate improvement on the declared criteria; do not substitute triangle counts, more features or a universal superiority claim.

Select tolerances from source precision, domain requirements and use, recording who adopts them. Include difficult conditions such as thin organs, junctions, wet/translucent surfaces, occlusion, moving contacts, scale transitions, low-light views and sparse evidence where relevant. Match cameras, illumination, scale, time and forcing when comparing. Preserve independent evaluation references; repeated tuning against them changes their independence status.

## Coding, checking and rebuild sequence

1. Finish the bounded implementation batch and independently review source/profile/API compatibility. Preserve preimages and keep the active ownership ledger current.
2. Freeze/pin the tested source and dependency profile. Reconcile external edits and running processes. Coordinator owns serial Cargo checks and the eventual Poet rebuild; workers do not start independent shared-target builds.
3. Run selected pure/native owner tests and targeted regressions that exercise behavior, invalid inputs and boundary conditions. Record skipped, failed, timed-out and unsupported cases honestly. Do not create tests that merely restate constants or mirror the implementation.
4. Exercise meaningful host/package/resource integration and the applicable GPU path, then rebuild Poet for the pinned qualified batch. Recheck only where later changes invalidate evidence.
5. Demonstrate the native user workflow and selected real production cases, recording actual operator/reviewer decisions. Technical execution and human acceptance are separate records.
6. Produce/qualify complete packages and consumer derivatives for the accepted scope. Preserve all unclosed IDs and limits.

This sequence preserves the user's instruction to defer Poet testing/rebuilding until coding is complete. Historical tests remain valid for their original snapshot and scope; they do not qualify newer source automatically. The user's pending M64 update pause remains applicable to the held asset export. This documentation set itself starts none of these checks.

## Resource and performance measurements

Measure source/project open, first useful preview, representative edit-to-preview latency, save/reopen, inference/query/estimate work, CPU and GPU memory, upload/stream residency and cancellation responsiveness. Name hardware/software/input, sample count and measurement method. Compare warm and cold states separately and disclose disk use, target/profile and cache state for builds. Do not invent limits or timings in this plan; record the case's adopted budgets before acceptance.

A logical operation counter is not a bound on every allocation. Measure/inspect source/session clones, decoder scratch, resident graph/mesh/media, GPU buffers and pending jobs separately. Preserve the complete master while selecting an explicit viewer working set. Consumer budgets affect derivatives rather than silently reducing the master quality ceiling.

## Receipt and review content

Every result binds source/dependency identifiers, input data/method/rule revisions, exact operation and parameters, actor/authority, outputs/digests, actual command/status, observed resource use, applicable acceptance criteria, failures/limits and review decision. Do not log restricted values or identifying context outside authorized storage. Use existing native provenance/review/claim owners for durable product records; Markdown is the human handoff, not a replacement runtime registry.

The pinned [production template](../tech/assets/model-production-template/README.md) governs complete models. Keep missing/partial/blocked/failed/unassessed/stale cases visible. N/A requires an applicable rule or authorized decision. No completed document, software check or single asset image closes a whole species, place or biosphere programme.
