28 October 2026. Proposed delivery plan for consideration; current activity is research/documentation. The [governing IP-00–09 plan](../implementation-plan.md) remains the phase authority. ## Product objective and boundaries

Deliver exceptional editable, evidence-bearing living systems and places through the intended Poet workspace, backed by QualiaDB and its controlled dependencies. Include terrestrial/aquatic organisms, habitats, Earth systems and solar-terrestrial forcing, with made-world/civics applications. Superiority is evaluated against declared references and competing outcome baselines: anatomical/geographic fidelity, usable editing, inference/explanation, material/motion/sound quality, reproducibility and measured cost. It is not inferred from library counts or universal superiority claims.

QualiaDB owns canonical graph, identifiers, logic, native domain/solver operations and resource contracts. Vibe owns authored orchestration with its pinned language compatibility. Poet owns the unified human authoring experience; preserve original tool-chest/manifold/source/knowledge continuity. Etalon is the developed GPU fork, Aether the controlled application framework, Webizen Desktop the launcher/host. Craft supplies internal reusable capabilities with notices preserved. Chora keeps its separate engine/workspace/licensing boundary. No imported framework becomes the new state, renderer or serializer owner by default.

## Change and migration method

For each packet: trace current public API → owning implementation → caller/host → source tests → saved executions. Reconcile all relevant nine-location owners and sibling crates, but do not turn whole-library reading into another first-output prerequisite. Classify the result as existing qualified behavior, existing unqualified behavior, missing binding, defect, or unassessed. Only then specify an additive/native change and a migration/compatibility case.

Inspect targeted algorithms from external Craft-origin references and preserve notices. Extract transformations into the established owner; do not import application state/UI loops/private IDs/transports. Reuse existing source/evaluation/HMC mechanisms. Repository modularisation should preserve public contracts and dependency direction; measure build improvements rather than assuming every split makes Cargo faster.

Each handoff records changed files/preimages, source/dependency pins, concrete behavior, actual commands/results, resource observations, failures, remaining IDs, and the next safe continuation. A source-only change stays source-only until checked. A successful test does not certify native usability or scientific validity. Supersede stale findings explicitly while retaining their historical evidence.

## Decisions for consideration

Existing tree/wallaby/local-place references are the starting cases already in the project. Further representative funga, invertebrate and microscopic subjects need explicit scope selection during production planning. Per-case scientific fidelity and visual reference targets, permitted datasets, cohort/method defaults and benchmark hardware must be recorded before acceptance thresholds are used. These decisions do not block useful source reconnaissance or erase previously authorized work. Estimate cost/duration only after those packets are bounded and existing implementation is reconciled.
