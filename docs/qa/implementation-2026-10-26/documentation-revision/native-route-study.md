## Existing state-to-package paths and the actual missing links

**Tree:** authored graph/organ parameters → existing graph/radius/turtle/sweep operations → native selected parts/materials → canonical accepted source plus .10d/Q42 resources → existing checkpoint HMC. That first usable editable-master path does not need new physiological solvers. Stable organ selection/editing, connected surfaces where required, sourced foliage/bark/material work and native contribution/review are substantive outcomes, not optional decoration.

The **optional development continuation** is authored identified state → admitted MetamerPlantGraph/LeafVascularSkeleton snapshot → existing sim step → existing Core botanical quins → identified geometry/material/state update. Earlier body reads establish pack_botany_metamer_quin/turgor/phenology and evaluate_botanical_frame in Core modalities/botany.rs. Fresh caller searches across sim, Core poet_host and native Poet did not establish a direct sim→quin→Poet integration; no engine-wide absence is inferred. Keep the adapter on sim/host side because sim depends on Core.

The state contract must map stable organ identifiers to current array indices and parent/creation lineage, declare thermal-time versus step semantics and preserve all authored overrides. Growth-cycle assimilation has no dt argument and uses fixed leaf-area/sink assumptions; record a cycle as such, not elapsed organism age. Preserve full u32 pipe counts and MPa state in the authoritative snapshot; Core metamer quins use u16 pipe lanes and turgor packers use kPa u16. Refuse or explicitly record lossy projection/quantization. A decoded quin is a useful semantic view, not a complete restart snapshot. The leaf conductance comment's unit should be reconciled with the existing formula before scientific claims; this does not block authored leaf geometry.

**Wallaby:** existing connected authored/acquired master mesh with normals/UV/part identifiers → existing weight authoring and explicit vertex lineage → existing SKL1 encode/attachment → existing SkeletalPlayer admission → actual animated-frame upload → identified native controls → existing guarded HMC save/reopen. Earlier weight-body review establishes weights_from_segments_into and remap_skin_weights_into in render/skeletal/authoring.rs; nearest one/two-segment weights are a starting tool, not accepted anatomical skinning, and index-remap does not solve interpolation after arbitrary remeshing.

The native assembly/viewport boundary remains the missing product connection. The retained static upload was previously inspected in native viewport/renderer.rs. Bind the real resource to current source and mesh lineage; retain authored rest pose, joint/clip identifiers, source graph associations, correction history and clip controls. Playback time/selection is runtime state unless explicitly checkpointed; player private buffers are not a portable save format. Source, edited rig/clip resources and a declared replay position can reconstruct the player after reopen.

No new tree generator, geometry engine, skinning implementation, SKL1 codec, HMC writer, rig player, renderer or rule framework is required by these findings. They do not rule out specific owner-level repairs discovered by actual integration. General contact/biomechanics can extend a usable rig later; advanced physiology is not a new serial prerequisite for the first authored master.
