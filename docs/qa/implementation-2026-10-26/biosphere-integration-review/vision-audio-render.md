# Vision, audio, and render source inventory

**Scope:** bounded source audit of `C:/github/QualiaDB/crates/qualia-vision/src`, `qualia-audio/src`, and `webizen-render/src`, with selected core implementation bodies and Poet call paths followed to establish what the public crate surfaces actually do. Exact read files/ranges are listed in the same-stem coverage JSON. No runtime, build, Cargo, or test commands were run. This inventory is source inspection, not a capability certification.

## Concrete functionality and exposure

1. **Vision product surface is mostly re-export wiring.** `C:/github/QualiaDB/crates/qualia-vision/src/lib.rs:8-38,88-138` exposes CV, bio, spatial, preprocess, model/weight and capability modules. `C:/github/QualiaDB/crates/qualia-vision/src/bio/mod.rs:1-3`, `C:/github/QualiaDB/crates/qualia-vision/src/cv/mod.rs:1-3` re-export implementations from `qualia-core-db::specialized_libs::computer_vision`; re-export does not itself establish a product host or runtime caller. The public list includes medical/histology operations, but these receive arrays and parameters rather than calibrated imaging metadata by default.

2. **Histology stain decomposition exists as an algorithm.** `C:/github/QualiaDB/crates/qualia-core-db/src/specialized_libs/computer_vision/bio/histopathology/macenko_deconvolution.rs:131-300` accepts packed RGB8 and optical-density threshold, filters tissue pixels, accumulates mean/covariance, then estimates stain vectors; output concentration arrays are caller-owned. RGB staining input is not a hyperspectral acquisition. This source does not establish specimen-specific calibration or diagnostic validity.

3. **Spectral unmixing exists for caller-defined channels/endmembers.** `C:/github/QualiaDB/crates/qualia-core-db/src/specialized_libs/computer_vision/bio/medical/spectral_unmix_nnls.rs:8-43,52-114,120-161` bounds the input at 16 channels and 8 components, takes column-major endmember vectors with no physical wavelength axis or units, performs 64 multiplicative NNLS updates, and reports abundances plus L2 residual; it supports ROI-mean and per-pixel paths. This is functional numerical unmixing given supplied spectra, not evidence the spectra/endmembers were measured or biologically appropriate.

4. **Marker-based segmentation is composed in source.** `C:/github/QualiaDB/crates/qualia-core-db/src/specialized_libs/computer_vision/bio/morphology/voronoi_otsu_label.rs:176-234` computes a 256-bin Otsu threshold, binarizes, distance-transforms, finds peak markers, watersheds inverted-distance topography, and zeroes background. It writes `u16` labels but allocates intermediate image buffers; source presence does not prove scale/performance or general microscopy acceptance.

5. **The public Canny-named edge routine is explicitly approximate.** `C:/github/QualiaDB/crates/qualia-core-db/src/specialized_libs/computer_vision/cv/edges/canny_u8.rs:1-54` applies Sobel magnitude and low/high thresholding with a repeated immediate-neighbor promotion loop; it is not full non-maximum suppression plus connected hysteresis. This matters when calling it an edge detector, not as a biological structure truth claim.

6. **Volume projection and shape feature paths are present.** `C:/github/QualiaDB/crates/qualia-core-db/src/specialized_libs/computer_vision/bio/medical/mip_project.rs:1-85` computes max-intensity projection along X/Y/Z from flat `f32` voxels and caller dimensions. `C:/github/QualiaDB/crates/qualia-core-db/src/specialized_libs/computer_vision/bio/radiomics/shape_3d_lite.rs:147-225` computes volume from voxel count × supplied spacing; for ≤512 coordinates it counts six-neighbour exposed faces using average face area, while larger sets use an AABB surface proxy. Caller-supplied spacing is not independently verified calibration, and the large-set surface is approximate by construction.

7. **Image-to-3D is a deliberately low-fidelity reference reconstruction.** `C:/github/QualiaDB/crates/qualia-vision/src/spatial/image_to_3d.rs:1-7,21-36,53-146` samples luminance onto a grid clamped 2..64, maps luminance to `z = luma * 0.35`, emits a planar heightfield and recomputed normals, then returns a `MeshIR` validation report and `ImageTo3dReceipt` with `is_reference_recon: true`. The source explicitly disclaims multiview SfM/foundation reconstruction; this is not scientific 3D microscopy reconstruction. `C:/github/QualiaDB/crates/qualia-vision/src/spatial/mod.rs:1-22` also re-exports mesh cleanup/validation/export and an explicit compile-to-10D handoff surface.

8. **One vision Vibe host route is evidenced; broad Poet vision use is not.** `C:/github/QualiaDB/crates/qualia-core-db/src/poet_host/invoke/vision/ahash.rs:1-24` parses bytes and optional dimensions into a `GrayView`, invokes average-hash and returns a `U64`; `C:/github/QualiaDB/crates/qualia-core-db/src/poet_host/invoke/mod.rs:531` dispatches `ids::VISION_AHASH` to this handler. The inspected binding is aHash, not the medical segmentation/unmixing or image-to-3D API. `C:/github/QualiaDB/crates/poet/src/browser/container_views_ext/senses.rs:11-69,76-137` constructs a Vision view with controls and fixed illustrative SVG/hash/resolution and a Listen view with fixed spectrum bars/RMS/F0 text; no algorithm bindings appear in these view builders. Those literals are not execution receipts or native scientific workflows.

9. **Audio crate exports real DSP and reference paths.** `C:/github/QualiaDB/crates/qualia-audio/src/lib.rs:42-97` publicly exports streaming STFT/log-mel/CQT, spatial mixing, capture, event/speech/music/generation and pipeline APIs. `C:/github/QualiaDB/crates/qualia-audio/src/pipeline.rs:1-110` shows `run_ears_demo` synthesizes a tone, encodes/stores/decodes WAV, computes log-mel and CQT, uses `ReferenceEventModel`, then compiles semantic quins; its result explicitly says reference, not P64 AED and no microphone. These APIs are executable source paths but were not run here.

10. **Capture is a shell-fed, consent-gated ring, not a device driver.** `C:/github/QualiaDB/crates/qualia-audio/src/capture.rs:1-94` requires granted intent before `start`, accepts mono `f32` via `push_mono`, drops oldest samples on overrun, and offers a pull buffer; comments assign native microphone hardware to the shell (`set_live_pcm`). Platform capture integration is outside this module and not established by this inspection.

11. **Spatial audio contains physically dimensioned propagation controls.** `C:/github/QualiaDB/crates/qualia-audio/src/spatial.rs:1-22,119-162,219-350,355-400` declares sound speed in dry air at 20°C as 343.2 m/s, listener position/velocity as metres and m/s, distance attenuation, direct-gain/lowpass-cutoff/diffraction/reverb occlusion fields, Doppler/panning evaluation, and caller-buffered mixing APIs. These are audio-spatial models, not organism acoustic sensitivity curves or measured habitat response.

12. **Renderer HMC texture stream has an actual planning/apply implementation.** `C:/github/QualiaDB/crates/webizen-render/src/volumetric_hmc_stream.rs:17-19,41-82,83-142,452-520` stores generation-stamped asset state and caller-selected residency requests; planning rejects duplicate or non-admitted interpretations and exposes admitted/deferred byte counts; apply checks generation/fingerprint, parses the bundle, prepares replacement payloads under a 256 MiB staging bound, and changes resident textures/material bindings. This source confirms algorithm and API presence, not a run receipt or a whole-HMC native Poet workflow.

13. **Native render preview has a concrete provider path; the biological/content workflow remains open.** `C:/github/QualiaDB/crates/webizen-render/src/poet_preview.rs:1-53` registers a `PoetRenderProvider` that invokes Vibe `RENDER_SCENE`, converts values to a `RenderScene` and returns a PNG data URI/diagnostic; `C:/github/QualiaDB/crates/qualia-cli/src/daemon.rs:178` registers it at daemon startup. `C:/github/QualiaDB/crates/poet/src/browser/render_preview.rs:105-121,207-277` calls the daemon preview endpoint and validates the PNG response. These are source-level browser request and registered-provider paths, but no current runtime receipt was read. `C:/github/QualiaDB/crates/webizen-render/src/lib.rs:1-85` gates GPU runtime, volumetric and native exports behind declared features/target cfgs; source exports do not prove the active build profile or adapter execution.

## Limits and evidence distinction

This audit establishes selected algorithm bodies, crate exports, and source-level host/provider links only. It does not establish compiled feature selection, installed native service state, live sensor/device input, actual execution for this task, accepted scientific/medical performance, species response, or contributor/reviewer source-to-output work. No prior execution receipt was inspected for these modules. Prior EMF spectral/shader findings are recorded separately in `emf-source-inventory.md`; they are not recounted as new source reads here. Other roots/crates, datasets, medical/source-instrument validity and other contributors' audit scopes are outside this inventory.
