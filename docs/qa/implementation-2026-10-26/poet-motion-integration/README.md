## What changed

The existing native assembly/material inspector now includes an editable material-key control. Users can load a selected material, add/update/remove ordered keys, choose Hold/Linear/CubicInOut interpolation, set an explicit millisecond sample, save/sample a track or remove its recipe while retaining current material factors. Changed local forms remain visible across stale source/selection changes and require explicit reload. This is explicit sampled authoring, not continuous playback, full compositing or biological simulation.

The same admitted project exposes `poet_material_motion_inspect` and `poet_material_motion_edit` MCP tools. They use existing source/context/authority guards and the same authoring operation as native controls. Keys are editable Vibe source in `poet_material_motion`, retained by the existing source journal/HMC path. No new document authority, scripting engine, format section, Cargo dependency or registry lock change is introduced.

Supported profile: version 1; at most 8 material tracks and 64 ordered distinct keys each; integer milliseconds 0..86,400,000; finite linear RGBA/roughness/metallic factors 0..1; explicit linear-material targets. HDR material extensions, arbitrary Bezier speed/influence, continuous transport, full EffectCraft project import and layer compositing remain open. Source-level checks cover preserving other fields; the fresh-process integration case uses an inline triangle/material engineering fixture, not a linked biological-resource package.
