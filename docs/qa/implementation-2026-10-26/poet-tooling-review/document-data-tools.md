## Shared integration assessment

The six repositories are MIT-claimed by their checked-in license files; PdfCraft and DeckCraft also declare `MIT OR Apache-2.0` at workspace level. Carry exact original copyright/license/NOTICE/ATTRIBUTION and vendor notices through any extraction. Headers and declarations are evidence of repository claims, not independent legal advice or a determination that every vendored dependency/asset is MIT.

The high-value reusable unit is the document/domain engine plus versioned commands, session/history and UI semantics. Poet should own one selected document/context and expose these through integrated content containers, inspectors, menus, palette, keyboard/accessibility behavior and native host services. Existing MCP/headless patterns in WordCraft, DeckCraft and CADCraft offer agent-facing candidates; PDF and Grid agent interfaces remain unassessed. Agent commands and UI gestures must resolve to the same session, revision, authorization and undo/recovery semantics. None of the sampled sources demonstrates that this integrated Poet projection exists.

QualiaDB duplication risk is **unresolved**, not zero: the nine-root reports in the integration review provide adjacent shared-capability evidence but were not semantic audits against each function/type in these six suites. Before extraction, map candidate text/style/layout, PDF codecs/annotations, formula/data/chart, presentation graph/media, image/provider controls and CAD geometry/constraint math to owning domains/modalities/solvers/specialized_libs/wgsl_forge/qualia-vision/qualia-audio/webizen-render/semantic_instruments and sibling qualia-sim. Reuse only where behavior, formats, provenance, ownership and execution evidence match. External protocol adapters, generated files and transitive dependencies were not comprehensively inspected.
