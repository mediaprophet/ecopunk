# Biological references: existing native capabilities and next seam

2026-10-26. **Source audit plus bounded implementation staged inside Ecopunk; no sibling source writes, build, test, GUI run, geometry production or biological qualification.** Working references, following the locality clarification, are mountain whitegum (*Eucalyptus dalrympleana* subsp. *dalrympleana*) and swamp wallaby (*Wallabia bicolor*) for Kosciuszko National Park / Snowy Mountains, NSW. These working names do not certify a particular occurrence, individual or anatomical parameter.

The native stack already contains useful plant and deformation kernels. The immediate obstacle is a **closed Poet graphical host profile**, followed by missing biological authoring/persistence contracts. Replacing the stack or writing a new tree generator is unjustified. Etalon is the developed fork; this audit finds no demonstrated Etalon defect requiring replacement.

## Why the current operator path stops

[`GeometryHost::capability_invoke`](C:/github/poet/native/src/graphical/geometry_host.rs:166) first checks the actual target grant, including dynamically selected IDs. Its match allows only `profile_sweep`, `revolve_profile`, `uv_sphere`, `torus`, `extrude_profile` and `swung_surface`; the default returns E300 “outside the admitted native geometry preview profile.” **Adding a turtle/colonization grant alone does not expose the existing kernel.**

[`NativeStudio`](C:/github/poet/native/src/graphical/ui.rs:100) has real source check/submit/save commands, dispatched through the worker/intent path. [`CanonicalEditorHost::submit`](C:/github/poet/native/src/graphical/controller.rs:339) uses the canonical persistent `SourceSession` and validates resulting preview data before promotion. [`mesh_from_invoke`](C:/github/poet/native/src/graphical/preview.rs:87) requires vertices **and** triangles. A graph-only colonization result cannot be its final visible value.

[`AuthoringEdit` / `GeometryRecipe`](C:/github/poet/native/src/graphical/authoring/mod.rs:69) covers rigid assembly, CAD, materials, UV and source parameters. [`PART_FIELDS`](C:/github/poet/native/src/graphical/assembly/part_input.rs:9) excludes rig/clip/groom fields, and strict admission rejects unknown properties. [`RetainedViewport::replace_scene`](C:/github/poet/native/src/graphical/viewport/renderer.rs:276) uploads static mesh/frame/material/UV data at line 332. Thus a native rig engine does not presently imply a Poet rig editor or animated authoring viewport.

The saved [R9 launcher](../../../../tools/poet-foundation/round9/open-equipment-trial.ps1) opens an equipment diagnostic HMC, with the equipment profile and three CAD grants. It is a useful existing source/session/viewport/recovery baseline, not a biological trial. R9 records executed equipment source-to-HMC/fresh-process recovery and retained GPU tests; it explicitly excludes human acceptance and leaves advanced rig/geometry work open. No plant/wallaby run is inferred from those results.

Poet's [`native/Cargo.toml:9`](C:/github/poet/native/Cargo.toml:9) selects Aether native and Qualia GPU features. [`Poet Cargo.toml:33`](C:/github/poet/Cargo.toml:33) patches wgpu/Naga to Etalon. [`etalon-render/src/lib.rs`](C:/github/etalon/crates/etalon-render/src/lib.rs:1) exports volumetric/HUD/EMF substrate; do not misattribute Qualia's botanical kernels or Poet's missing operator admission to that crate. Existing R9 execution is the applicable saved consumer evidence; this audit did not re-resolve dependencies or run a GPU.

## Bounded next implementation and checks

Track 1 now has a [reviewable staged patch](../../../../tools/poet-foundation/biological-reference/README.md) with pre/post hashes, strict borrowed-input admission and seven supplied unrun tests. It is not installed or execution-qualified. The remaining scopes below are follow-on requirements, not authorization to edit sibling repositories.

1. **Expose the existing turtle kernel first in Poet's GeometryHost.** Add the exact `ComputationalGeometry.turtle_3d` match and bounded preflight before forwarding to `PoetSnapshot`; retain actual-target grant checks. Validate command list/row shapes and supported tags, finite numeric arguments, bounded command count, ring tessellation and explicit capacity. Use checked arithmetic for output/scratch cost and charge dispatch plus conservative command/tessellation work before Core's allocation. Core currently accepts caller-selected `capacity` (default 8192), so forwarding unexamined inputs would bypass Poet's working-set protection. Refuse excess input; source cannot increase host limits. Do not reimplement geometry, weaken admission globally, or represent a command interpreter as a finished growth system.
2. **Prove that seam through source/session/recovery, then expose graph operations separately.** Test an authorized real-kernel branch/tropism/leaf mesh through `SourceSession` and preview admission, output coordinates/topology, denied static/dynamic targets (E300), excessive command/tessellation/capacity/scratch/work requests (E400), malformed/nonfinite inputs, unchanged revision on rejection and HMC fresh-process replay. Tests must invoke the actual kernel, not a mock or duplicate formula. Existing [`geometry_host.rs` tests](C:/github/poet/native/src/graphical/geometry_host.rs:220) provide the grant/kernel pattern. For colonization add attractor/seed/parent/capacity/iteration validation and a conservative node × attractor × iteration work bound; then expose existing radii and authored graph-to-turtle orchestration. Preserve graph/root/part identifiers and development state. A positive source-evaluation case is a narrow engineering qualification; actual contributor/reviewer interaction remains required.
3. **Author a sourced development contract and native plant controls.** On the existing source owner, define stage/time/environment/seed semantics and stable organ/branch correspondence before parameter-to-source controls. Retain stage-specific leaf/branch/material data and edits through regeneration/undo/checkpoint/reopen. Integrate source-owned biological parameters and part selection in Poet; qualify alpha/wind/picking and developmental transitions on the named whitegum. A sequence of unrelated static meshes or generic iteration slider cannot close this outcome.
4. **Carry organic topology, rigs and clips through existing owners.** Specify editable master/topology and part/rig/UV/weight lineage, then extend Poet admission/checkpoint/viewport contracts to the existing skeletal codec/player/upload APIs. Add native rig/weight/clip/transition controls with edit/undo/reopen/deformation checks; qualify root motion/contact and required behaviour only against sourced wallaby anatomy. Reconcile existing groom owners before commissioning missing shared capability; then bind guide/surface resources, deformation, controls and target-specific rendering. Human-oriented body fit, DQS-only vertices or grass blades cannot stand in for this work.

All tracks retain the native no-JS/Node/V8 workflow and one authoritative source/session. General shared capabilities remain with QualiaDB/custom dependencies; Poet owns profile, controls and integration. Species facts, rights, editable masters and derivation remain in the HMC embodiment. Record the catalogue/dossier and all required expanded cases before model claims. **Neither species package is complete; film, open-world-game and cartoon targets, their full inventories/claims, biological evidence and human acceptance remain open.** This document makes no model-completion claim.
