## Product boundary and destination

EffectCraft is a standalone After Effects-style compositing/motion-graphics editor with its own project/session, command registry, UI, command-line/MCP/control clients and renderer. Its reusable interaction value is the editing flow (composition/layer/property/timeline/effect/job/history), not its app name, Adobe-parity chrome, independent shell or requirement for an EffectCraft-branded Poet app. Use Poet's existing **Construct → Manifold → ToolChest** model carefully: a Construct is a coherent observer/agent scope, not an EffectCraft project or app (see QualiaDB `docs/manuals/adr/0012-construct-is-the-distributable-composition.md`); a Manifold provides an editing lens and seed layout; ToolChest discovers available tools/actions. Keep EffectCraft-like project state in the relevant project/media domain and route authority through current Poet/QualiaDB owners. A future media/animation surface belongs as containers/panels/actions inside an appropriate Poet Manifold, retaining Poet's existing controls and session behavior.

In the inspected Poet WASM catalogue sources, the `projects` Manifold seed contains a `timeline` container; the `studio-bay` first-arrive seed is empty. These are source-seed observations only: they do not establish the selected defaults of the native workspace or every Poet runtime. `ConstructSeed` models observer/agent scope and records bundled/authored/stub status; `ManifoldSeed` describes initial containers, connections and panels. I found no EffectCraft-specific seed or handler in the scanned Poet WASM catalogue paths. Existing catalogue stubs have no Manifold and are not live tools. The destination below is a product mapping to existing Poet concepts, not a claim that an EffectCraft editor currently runs in Poet.

## Domain distinctions, limitations and follow-up

EffectCraft's 3D-related interactions serve compositing: camera/light layers, imported/extruded models, layer transforms and rendered integration inside a composition. This is not organism anatomy, anatomical/topological editing, rig completeness, scene ecology, simulation or an HMC embodiment. Its timeline organizes authored shots and keyframes, not QualiaDB simulation state. Useful editorial behavior can consume rendered images/video from upstream owners; it cannot replace the production renderer, geometry/simulation authorities or model claim ledger.

Agent access is a strength in source design: one command registry is described for UI/CLI/control/MCP, and gestures emit command-backed edits. This review did not inspect automation/MCP body files or establish transport reachability, permission enforcement, actual agent use or native Poet use. EffectCraft docs say the renderer/other surfaces share a Session; this report has not verified any runtime. Current Poet facts here are WASM source-seed observations only: the `studio-bay` seed is empty, the Project Manifold seed includes a timeline container, and catalog stub Constructs lack Manifold seeds. These findings do not establish native workspace defaults. Whether a published/native runtime currently marks a particular service unavailable is not inferred from these source seeds. Accessibility is unassessed: keyboard shortcut presence is not evidence of screen-reader semantics, focus correctness or WCAG acceptance.

A safe next research slice is a small interaction-to-intent mapping for one representative timeline edit and one effect/property edit, attached to the appropriate Poet Construct/Manifold and current host owner, followed by the coordinator's source/host review. It should preserve existing Poet functionality and use reviewed source/output IDs. It must not introduce a standalone app or assume every EffectCraft command belongs in Poet. That is a proposed follow-up, not authorization for implementation in this documentation pass.
