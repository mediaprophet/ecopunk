**Reuse the lower document/command/render capabilities inside Poet, through its existing native authorization and shared-state patterns. Do not import the fully wired EffectCraft host as Poet's runtime.** The inspected engine already supports identified compositions/layers/properties, undoable edits, exact-time keys, effect-stack dispatch, project serialization and rendering. The full host installs Boa JavaScript expressions/scripting, direct file/media services and optional plug-ins. These mechanisms do not supply Poet authority, Vibe semantics, complete HMC recovery or human acceptance.

This review follows **two selected source routes** with fourteen implementation/caller body files. It does not audit all effects, codecs, plugins, dialogs, tools, target combinations or the complete dependency closure. README/architecture command/effect/parity counts remain source-maintained claims; no functional count or global quality conclusion is made. Additional files listed as API/call-site/discovery-only were not promoted to semantic body review.

## Route 2: an agent invokes the same engine; selected export producer

`automation/src/tools.rs:111–120,197–200` resolves a tool and routes `execute_command` to `Backend::exec`. `backend.rs:33–85` owns either an in-process boxed Session or a bridge; headless calls `Session::execute_checked`, bridge calls `engine.execute` on the running app. The MCP server call is located at `automation/server.rs:270` (call-site-only here). Tool registry entries for execute/add-key/render/open/save are at `tools.rs:572,663,728,747,756`. `render_frame` (`:393–408`) calls the same backend render path and optionally writes PNG; `open_project/save_project` (`:411–430`) invoke the file commands. This is concrete agent transport reuse, not evidence of live UI parity or enrolled actor authority.

The selected native export producer is `host::FileExporter::export_async` (`host/lib.rs:40–78`): it marshals the engine's identified project/queue item/footage/optional expr/accel into `effectcraft_export::Job`, maps progress and returns actual path/frames/bytes/audio/log fields. `export/lib.rs:166–210,255–287` dispatches formats; the image-sequence body renders batches through its pipeline, encodes in memory, creates/writes/finishes each output and advances progress. Pipeline frame/output internals and every codec are outside this body scope. Engine queue call sites `engine/render_queue.rs:286–297` connect the exporter; `commands/render_queue.rs:1048` registers `renderQueue.render` (call-site/API-only, not a full job-owner audit).

**Cancellation verified in this body scope:** export `State::advance` (`export/lib.rs:225–228`) returns `Err(Cancelled)` when progress callback returns false; `export_async` (`:178–180`) requests cleanup before returning, and `FileExporter` maps this to the engine's cancelled marker (`host/lib.rs:76`). It is batch-boundary cooperation, not preemption or guaranteed rollback of external effects. Cleanup's pipeline body was not read. MCP long-job cancellation handling/no-response branches were located (`automation/long_job.rs:136–139,168–170`) and documented in `docs/mcp.md:54–85`; the complete notification/job lifecycle was **not** body-audited. Do not infer that every render, nested batch, bridge call or `wait:false` request has the same cancellation acknowledgement. Poet's existing native IntentBus currently rejects unsupported cancellation honestly; only advertise a new cancel state after its exact producer/result semantics are connected and qualified.

## Runtime and policy seams that prevent a whole-app import

| Boundary | Current source evidence | Required treatment inside Poet |
|---|---|---|
| Boa and authored language | `host::session` (`host/lib.rs:84–97`) installs `effectcraft_expr::Expressions`, syntax checker and `effectcraft_script::install` unconditionally. Expr/script manifests depend on workspace Boa 0.22; lock pins `boa_engine 0.22.0` to crates.io. Script runtime/prelude and expression loop-limit locations were discovered, not body-audited. | Keep Vibe as authored language. Default `Session` has `expr=None`, no exporter/importer/accelerator (`engine/lib.rs:568–588`), so lower engine/render construction is the seam for a separately qualified non-JS profile. Omitting Boa does **not** preserve expression-bearing projects: detect, retain source text and hold/report unsupported expressions/scripts until an explicitly compatible Vibe/native binding exists. Never silently unanimate them or add a JS fallback. Do not describe pure Rust Boa as satisfying the native no-JS rule. |
| GPU/device | Workspace manifest `Cargo.toml:104` and lock `:6306–6309` select registry wgpu 30.0.1; no selected manifest names local Etalon. Render `Accelerator` (`render/lib.rs:406–442,498–513`) is a typed optional interface; GPU methods may decline and CPU remains the fallback. | Reconcile this trait with existing Etalon/PortalGpu/device ownership and exact image/colour/effect-space contracts. Registry wgpu is not evidence of the developed Etalon fork. No second GPU/device graph, blanket dependency swap, performance superiority or native/WASM compatibility is established. GPU implementation/shaders remain unreviewed here. |
| Files/effects/plugins | Session default uses unrestricted FsServices; Services defaults also access filesystem metadata/directories (`engine/lib.rs:99–145`). Plug-in command `effect.plugins.load` (`commands/effect.rs:36–70`) directly lists a supplied folder, reads bytes via services and invokes a host loader. Host enables loader only when plugin runtime is available. Plugin manifest offers optional wasmi; native host enables it. | Bind authorized native files/resources and default-denied capability exposure. Replacing only `read_file/write_file` is insufficient while other service defaults or direct `std::fs` paths remain reachable. Wasmi/sandbox/fuel descriptions are not audited containment or delegated permission proof. Keep external modules held until loader provenance, memory/fuel/cancellation/effect rights and registry lifetime are qualified. |
| Agent policy/validation | `Backend::headless/bridge` default `confinement=None` (`backend.rs:33–39`); optional `confine` checks before `exec`. `render_frame` directly writes an optional path (`tools.rs:398–402`). `commands::params_schema` derives property descriptions from prose and does not generate typed value schemas; `check_params` only rejects recognized unknown top-level keys and returns success when it cannot parse the accepted-key description (`commands/mod.rs:344–384`). | Reuse native Poet's admitted session, SourceRef, authorization, expected revision, budgets, shared command contract and receipts. Do not treat generic MCP, optional path confinement, availability or generated prose schemas as those checks. Write only the strict selected command envelope/typed conversion actually required; do not commission another auth/graph/contract system. |
| Safety claim / licensing | AGENTS forbids unsafe and workspace declares `unsafe_code="forbid"` (`Cargo.toml:135`); this is a source policy, not a transitive dependency/runtime audit. Workspace license is `MIT OR Apache-2.0`; MIT option and required notices must survive selected reuse. Source asset/brand/corpus rules are separate. | Preserve notices and origin map, inspect chosen dependency/features and test data; do not import branding/assets/account state or claim every third-party dependency is unsafe-free/permissively redistributable from a root manifest. No safety enforcement or project-wide crash-freedom was executed here. |
