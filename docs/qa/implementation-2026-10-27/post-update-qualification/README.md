## Corrective implementation authorised

Timothy subsequently directed that the problems be resolved in code, with an excellent error- and warning-free solution. Three disjoint workers prepared candidates; the coordinator reviewed and saved 39 source files against original hashes and owns all serial Cargo checks. The [installation receipt](repair-install.json) records that save, not verification. Follow-up receipts below preserve subsequent corrections rather than rewriting that history.

- Runtime: task scope/ownership, effect catalogue, same checked context, terminal/deadline/executor handling and explicit unsupported standalone paths. No script-supplied scope becomes a human delegation.
- Store/Poet: per-artifact nonblocking publication state instead of unrelated global-lock contention, with complete mutation/replacement/poison lifecycle checks; distinguish accepted source from optional preview status.
- Quality: no-allocation logical revocation and explicit bounded interrupt-history behavior, truthful commitment versus unavailable ZK-provider APIs, and actual unused-code/import cleanup without blanket warning suppression.

The native source-stamp trace is `SourceRef::check_current` → `studio_store::artifact_stamp_is_current` → process-global `try_lock`. A busy unrelated artifact can therefore produce the same Boolean refusal as stale/absent state. The isolated pass and source trace support this diagnosis; do not reinterpret ten parallel failures as ten independently demonstrated Vibe regressions. The separate surface receipt/preview classification remains subject to regression verification. Tests must remain parallel-capable; serializing the whole harness is not the product fix.

Bytecode scoped-task and dynamic-host routes refuse before effects. Terminal results are runtime-owned, and cancellation of a running native call is acknowledged only when its executor reaches a checkpoint; earlier external effects may still require reconciliation.

Compatibility: old cached chunks with a branch/function target outside actual instruction boundaries, including a one-past-end target emitted by the prior conditional compiler, now refuse admission. Regenerate that optional bytecode from the preserved authored source; the AST/REPL source path remains available without a per-script Rust build. The compiler now emits an actual function-end landing instruction. `CallUser` operand metadata now matches its existing u16 index + u8 argument-count wire layout; no new wire-format version or released Vibe dialect is claimed. Pure cells can no longer register tasks, and numeric-only/foreign-scope task references refuse; these are intentional admission changes.

Interrupt history has 64 preallocated retained slots and a saturating overflow counter; every lease reader respects the revocation latch. Overflow may drop an incoming event's owned strings. The unchanged timing assertion measures the trigger path only, not universal allocator latency or rollback of external effects. Clone/resume tests check reservation and revocation behavior.

Legacy `crypto.prove_zk_predicate` and `crypto.verify_zk_predicate` now explicitly refuse without an admitted proof provider. The new deterministic SHA-256 commitment operations return records that distinguish content integrity from predicate truth and issuer authenticity. They provide no witness privacy, adopted authority or ZK verification. This is an explicit compatibility change, not a claim that the missing proof provider is implemented.

Existing Option/null, byte/grapheme length/index and noncapturing-lambda behavior retain explicit compatibility status. Do not call these absent language families or silently change pinned 0.1 behavior to the proposed 0.2 contract.

The current package still declares `vibe-0.1` / `vibe-host-0.1`; new code and test counts do not certify an entire released 0.2 profile.
