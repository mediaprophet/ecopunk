## What the current code and receipts actually establish

- **Direct project contributor:** Poet native_project.rs:170–219 constructs CanonicalEditorHost → CheckpointEditorHost → optional ResourceImportHost → SharedEditorHost → AuthorizedEditorHost, under NativeAuthorityOwner with an authenticated SessionHandle; selected UI attaches SelectedAuthorityOwner at 224–237 and MCP uses connect at 239–244. cooperative/editor.rs:181–200 checks ReadSource plus ExecuteSource for rig work and ordinary ExecuteSource for source edits. These are direct acting-controller/role/source checks, not a human-to-agent chain.
- **Delegation candidate, not permission:** QualiaDB native_authority/delegation/inspection.rs:9–10,38–118 states inspection does not grant a session, durable adoption, resource consumption or side effect. It verifies root scope/current document and signed chain, then checks leaf/controller and ancestor operation. Its verify_chain call supplies an empty cancellation list at 75–85. Session state session_state.rs:15–24 contains subject, grant and binding but no adopted delegation ancestry. Native dispatch is therefore not demonstrated to enforce an adopted chain by this selected trace. Do not treat source present as execution qualification.
- **Review and contributions:** QualiaDB native_authority/records.rs:88–165 binds a requested source decision to current revision and appends its decision ID durably; Poet cooperation_selection.rs:18–70 projects exact source/package requests and linked current-source decisions, while cooperative_controls.rs and package_review_controls.rs are the native presentation. The later [swarm report](../human-authority-round1/swarm-implementation-result.md) supersedes the older round README’s “running” status and unanswered-only selector wording: multiple decisions can be selected, with source decision context shown. This is software-owner scope, not independent human or delegated ancestry acceptance.
- **Rig cooperative example:** The same owner route now sends selected-resource rig edits through current read and execute checks and canonical source submit. The [rig results](../human-authority-round1/swarm-rig-adoption-check.log) report 14 passing selected cases, including CPU viewport adoption and signed synthetic non-GPU existing-binding save/fresh reopen; they do not establish a signed initial adoption through actual viewport, GPU animation, or human use. The [native library log](../human-authority-round1/swarm-final-native-lib.log) reports 321 pass, 0 fail, 13 ignored. The final executable receipt is [swarm-verification.json](../human-authority-round1/swarm-verification.json); its CLI public-configuration smoke opened no window or credentials.
- **Earlier scoped authority results:** [cooperative-delegation.json](../human-authority-round1/cooperative-delegation.json) reports 143 pass and [core-controller-authority.json](../human-authority-round1/core-controller-authority.json) 77 pass for their captured prior snapshots. Their specific native candidate composition and QDNF tests are not new end-to-end delegated-agent authorization, current aggregate budget enforcement or independent review.
- **Agreements and funding:** the selected [agreement handoff](../../../planning/tech/semantic-agreements-and-compensation.md) inventories existing license, humanitarian-equity-framework, semantic-tokens-xec and QualiaDB semantic_instruments, cooperative project/commons and QDNF economics; these are sources and referenced tests, not new executed agreement adoption or settlement. ## Execution order and boundaries

First validate one directly admitted source-edit/save/reopen/review workflow with a real operator and explicit source rights; the initial engineering fix can proceed while unresolved domain quality review takes place. Parallelize contract/owner research for delegated chains and agreement/rights without blocking that direct path. For a delegated route, compose existing native/cooperative/QDNF owners, then qualify durable adoption, leaf login, actual operation/publication rechecks, UI and reviewer ancestry. Agreement, finance and token work remains required for its applicable product cases and need not be paid-service work to establish the first authoring result. One coordinator owns shared source/manifest registration and serial checks; jobs must pin exact owned files/preimages and existing consumer, avoid simultaneous edits and preserve all previous receipts.
