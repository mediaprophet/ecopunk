# Native Poet cooperative integration — source inventory

**Scope:** read-only next-step map after the current authoring diagnostic. This inventory is not a source change or a cooperative-production acceptance claim. No tests were run.

## Current canonical seams

1. **Project and membership state.** `qualia_cooperative_core::projects` exposes `Project`, `ProjectMembership`, `ProjectRole`, ID/envelope builders, and contribution derivation. These are value types and pure builders; no call site in the inspected Poet host persists or admits them. Exact legacy record identifiers are `urn:wellfair:project:{uuid}`, `urn:wellfair:project_membership:{uuid}`, and `urn:wellfair:contribution:{uuid}`. Keep these distinct from `StudioArtifact.id`, its `did_q42`, document/source identifiers, and revisions; none is a universal identifier for the others. Current Poet cooperative invoke exports only `CooperativeDelegation.permits` and `CooperativeWork.board_project`. The role enum contains Steward, Contributor, Observer; it has no Reviewer role. Next: use the existing Wellfare/Qualia project and rights owner for project membership state and admission. `ProjectMembership::new` or a caller-supplied identifier is not proof of membership.

2. **Host principal identifiers and authority.** `delegation_permits` fails closed for revoked, ineffective consent, invalid time, inactive trigger, wrong domain, unauthorized selfhood, missing consequential provenance and jurisdiction mismatch. The Poet wrapper accepts delegation/request/context as source values, defaults time to zero, and does not authenticate them against the invoking native principal identifiers, project membership, or artifact revision. `PoetSnapshot` and the inspected invoke dispatch signature do not carry caller/member principal identifiers. Next: bind the authenticated native host principal and current authority view at dispatch, then check project/action/target/revision before writes using existing native QDNF/authority owners. Do not build a Poet-local principal-identifier or authorization store.

3. **Studio source and revision binding.** `StudioArtifact` is held in a process-local `OnceLock<Mutex<BTreeMap<...>>>`, beside its source journal. Its public shape has local artifact ID, Q42 key, domain/title, Lamport clock, nodes/properties/history; it has no project, qualified source/document reference, or contribution lineage. The store now also provides opaque process-local `StoreStamp` incarnation/revision guards: `create_artifact_if_absent`, `get_artifact_stamped`, `mutate_artifact_stamped`, stamped undo/redo, and a cheap current-stamp check. These guard stale/replaced in-memory edits but explicitly are not durable checkpoints, identifiers, or authority grants. The older `mutate_artifact_at` makes numeric expected revision optional and is explicitly not authorization; `studio_edit` also accepts an omitted expected revision. Compatibility `upsert_artifact` skips revision/authority checks and resets the in-memory journal. Next: connect the artifact to qualified project/source/document identifiers and require host-authorized stamped/revision-bound mutations for cooperative edits, keeping local compatibility usage explicitly separate.

4. **Contribution and reviewer records.** `Contribution` supports project/contributor, descriptive effort/capital/ROI/time and predecessor chaining, with immutable dedupe/obligation derivation, but has no source/document/revision reference. No project review/admission API was found in the inspected Poet invoke paths. QDNF `IndependentReviewPacket` is explicitly prepared and unsigned crypto review, not a project reviewer decision. `shed_registry::coop_contribution_log` falls back to `proj-default` / `did:q42:local-self`, returns `logged`, and writes through compatibility Studio upsert. Next: only after real member admission, link each contribution to its exact source/document revision; record an actual authorized reviewer decision against that revision through the existing project/rights owner. Do not synthesize principal identifiers, reviewer roles, acceptance, or monetary valuation.
