# Independent AO precision source review

All seven candidate hashes match the frozen manifest. I inspected the complete producer/consumer diffs, native camera/uniform factory, target creation/reset, warm render ordering, settings, and the strengthened pixel oracle. No source-format/consumer mismatch blocking the declared finite-camera repair was found. This is not GPU or high-grade visual acceptance.

The prepass packs log2(1+world-view-depth), with native far 15000 and scale log2(15001)/65534. Both reconstruction and mesh bilateral sampling use the matching exp2 inverse. Zero remains background; each consumer rejects zero before subtracting one, while code1 remains a valid zero-depth surface. All producers/consumers agree on the exact tag1 in the previously reserved uniform lane; unsupported tags discard/return neutral AO. Changing camera near does not alias the background sentinel.

For cold/warm state, both initial and per-frame uniforms use the same factory. The render command copies that uniform before recording AO passes. The prepass clears BA to zero and AO evaluation clears white each recorded frame. Targets, views and bind groups are recreated together on resize, and AO pipelines use embedded shader modules with cache=None. The public setters cannot change the internal encoding version; old transient GPU targets cannot survive into another coherently rebuilt binary. The proposed two-frame hole/solid test exercises reuse of the same target after the fix, but that actual post-fix GPU run is still missing. Disabling AO leaves bytes allocated but the mesh consumer returns neutral under enabled=0; re-enabling records and clears the current-frame targets before their use.

One concrete limitation must remain explicit: cfg(test) encode_depth rejects nonfinite depth, but the runtime AO factory/public AO setters only clamp radius/strength/bias and do not sanitize NaN. Camera direction normalization has a fallback, while camera yaw/pitch/target/eye are not comprehensively finite-validated by the existing public setters. Those original input-admission limits are not introduced by this proposal, but the five CPU tests cannot establish arbitrary invalid runtime input rejection. The settings owner needs reject/preserve validation and focused tests before claiming that behavior.

Actual GPU qualification remains the blocking evidence item: run the unchanged-and-strengthened native mask depth test and relevant AO/material family using the coherent final binary, including its consecutive cold/warm frames. CPU log/exp equations and Naga acceptance do not show GPU precision, performance or high-grade visual acceptance. The new logarithmic step improves near reference precision without adding attachments, changing fixed uniform size or introducing per-pixel CPU/unbounded work. It does not certify all fine features through 15km; far-distance relative precision and intentional world-unit AO settings retain their declared limits.

No code edit, Cargo command, GPU execution or sibling mutation was performed during this independent review. See independent-review.json for per-topic findings and exact candidate pins.
