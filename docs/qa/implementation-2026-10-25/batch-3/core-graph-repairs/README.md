# Native graph and CML repairs

These changes address five observed failures from the actual canonical core run. They do not share one technical root cause. `verification.json` preserves each exact original failure output/location and the focused checks; no remaining full-suite failure is waived.

| Observed failure | Inspected cause | Bounded repair |
|---|---|---|
| Turtle empty-prefix ingest expected Commons flag | The RDF/Rio parse and Q42 publication succeed, but the test assumes parsing grants public redistribution. Native QW-10 requires an explicit reviewed policy and default ingest stays unmarked. | Test-only correction keeps publication unmarked, requires both source triples, full empty-prefix object IRI and a populated native lexicon. Production ingest/rights behavior is preserved. |
| `SERVICE <local:graph>` reported a remote endpoint | The grammar hashes even the exact reserved local-default handle into an unrelated endpoint number. The existing executor admits its reserved local sentinel or an actual matching native graph context. | Resolve only exact `local:graph` to the existing local sentinel. Other local/qualia/did references keep their distinct identifiers; HTTP egress and variable SERVICE remain refused. |
| Solid Turtle export loses original Alice/knows URI labels | `Q42Lexicon::from_volume` and its context adapter use borrowed `lookup_hash`, which intentionally cannot reconstruct native namespaced v4 lexemes. | Use existing native `lookup_owned` and preserve every original stored hash-to-term association. No rehashing, replacement lexicon/format or unqualified equivalence is introduced. |
| C2PA field presence reports IntegrityChecked | SPARQL-MM infers integrity, signature and even trust-chain success from nonzero RDF references, despite its own signature-verification method explicitly having no verifier. | Keep metadata/provenance access intact but return ParsedOnly when manifest/signature edges exist, Unsupported without them. Graph claims, certificates and claimed roots cannot fabricate a verification tier. Higher statuses require a separately integrated actual native verification result. |
| Compact CML source loses `stroke="#000"` | The line-based importer sees no nested tags on a compact line, and its node attributes target BTree order instead of the currently open XML node. Its exporter also emits unescaped attribute values. | Add a focused directory-backed CML adapter using the existing native quick-xml 0.41 engine. Parse a detached source candidate completely before assignment, preserve title and explicit property/node/attribute values, track the actual open node, and export escaped XML including numeric attribute-whitespace references. |

The CML profile rejects malformed XML, DTD/external entities, unknown/misplaced elements or attributes, duplicate source keys/node identifiers, caller-domain mismatch and exhausted byte/field/depth bounds. The host selects the local record identifier/domain and retains its revision/authority envelope; file `did`/`clock` fields do not create a grant or replace it. This remains the legacy editable-source CML projection, not a complete HMC embodiment or an agreement/adoption receipt. Native properties carrying explicit source/rights/provenance text survive exact roundtrip. A broader qualified source-identifier mapping is separate from treating imported text as authority.

The new CML module exposes caller-selected cold limits. Its legacy import/export wrappers use bounded defaults; larger native caller-selected budgets remain possible. All new implementation files are below 500 lines. Ownership review kept the existing grammar change confined to endpoint lowering, reduced the existing C2PA accessor's unsupported branches, and changed only a test in the oversized ingest file. StudioStore remains a router to focused CML code and preserves the already-applied checkpoint/serde/journal contracts. No new behavior was appended to its unrelated format paths.

## Executed focused evidence

`run-checks.ps1` invokes rustc directly against actual cached native core codecs/AST/planner/executor, the exact candidate sources, unchanged actual parser/daemon-query/Solid exporter source, actual StudioArtifact, existing native quick-xml 0.41 and real Rio ingest. No mock HMC/Q42/XML/parser engine or fake verification record is used. The focused cases cover:

- Native namespaced v4 Q42 volume to full terms/original hash associations and context mapping.
- The unchanged real Solid exporter test, including exact original URI labels, plus its sanctuary-without-choice refusal.
- Candidate SERVICE grammar through the actual parser/planner/executor and the existing local SERVICE test; only the exact reserved local-default handle collapses to that sentinel.
- Original C2PA non-escalation plus a graph containing manifest/assertion/signature/certificate/claimed-root/isVerified/status claims, all remaining ParsedOnly with verification false.
- Compact CML styles, open-node ordering, Unicode/XML escapes/attribute whitespace/source-rights property roundtrip, and malformed/unknown/duplicate/domain/budget failure without partial source change.
- Actual Rio Turtle empty-prefix ingest to Q42, with full lexical source retained and no implicit public-redistribution flag.

The first focused link lacked the native Windows 0.52 library search path; its error is preserved. An initial 11-case compatibility run accidentally selected cached quick-xml 0.36.2; that evidence is separately retained, not described as the selected native dependency. The final runner selects quick-xml 0.41.0 explicitly and uses its current decoded-and-normalized attribute API. Verification pins identify the actual dependency and test binary. A known unrelated helper is unused in this narrowed harness; no warning is represented as a test failure or broad qualification.

The modified StudioArtifact import/export dispatch is source-reviewed but is not executed as a rebuilt whole core in this narrow harness; the actual adapter executes against the current native source type. Parent owns the one coherent post-apply full-crate check. The original broad core run remains failed until its separate failures are resolved/qualified. Exact C2PA cryptographic payload verification, complete Solid JSON-LD/other-format interpretation and full model/package acceptance are not claimed by these scoped repairs.
