# Checkpoint replacement resource preservation guard

The core decoded checkpoint currently retains source/journal records, not the complete inert resource set. Re-encoding that record with an empty asset list cannot preserve all prior geometry/Q42/media/unknown entries. An expected file SHA protects conflicts but does not authorize erasing those resources.

`poet-preservation-candidate/checkpoints/mod.rs` now reads existing replacement bytes under the caller file-byte budget, fully decodes the same bytes, checks their source association and exact expected SHA, and inspects their native HMC index. It refuses every replacement containing anything beyond the one native source resource, including when the caller supplies a new asset list. The error explicitly states that complete resource preservation during replacement is unsupported and existing bytes are preserved. This refusal occurs before source capture/encoding or file writes. Source-only checkpoint replacement remains supported, retaining the actual native restart test path. Newly saving a package with real derived assets remains supported.

The separate followup manifest preserves previous source freezes and pins the actual module after the authorised-reopen route was applied. No Qualia core file is changed. Two new staged tests use actual compiled native .10d/Q42 resources and a native HMC text entry, respectively, to require refusal and byte-for-byte preservation, including when another asset list is supplied. They are formatted but unexecuted pending root's actual native build. Full inert-resource preservation/re-emission remains implementation work; this guard does not pretend it is implemented.
